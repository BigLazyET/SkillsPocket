# AI 编剧与逐镜制作稿

用户提供主题、目标、受众或素材就可以开始。AI 负责调研、写稿和安排镜头。用户审阅方向、事实和要说的话。已有稿件可作为输入。

## 1. 把需求写成制作简报

记录目标观众、观看场景、目标时长与画幅、看完要理解或完成的事、必讲和禁讲内容。产品介绍还要明确演示目标和行动引导。技术讲解还要记录版本、操作前提和适用边界。缺少次要偏好时给出可逆的默认方案。缺少主题、核心目标或关键事实时，只问影响创作的最少问题。

把调研写进 `production/research.md`，包括主题事实、观众可能卡住的问题、可用的画面参考。给事实编号（如 `F01`），记录来源链接或用户文件及能支持的具体说法。区分事实、用户提供的个人体验和待核实内容。发生冲突时标出来，交给用户决定需要保留的说法。私有产品数据、经历和效果数字仅用用户确认的内容。

## 2. 在写分镜前盘点可用素材

按 [通用素材的选用顺序](./resources.md#通用素材的选用顺序) 先看当前工程、所用 Skill 和模板有哪些可复用资源，同时核对用户明确指定的素材和真实演示所需的文件。图片、音效、动画和特效等可直接选用合适的自带资源。记录稳定素材 ID（如 `M01`）、路径、内容、可用的源片段、用途和限制。视频检查画面、时长、入出点与原声，动画和特效检查格式、透明背景以及可复用部分，图片检查能否裁到目标画幅。指出哪些信息可由素材证明，哪些只能作图解或装饰。尚未读取的素材标成待核对。

用这份盘点给镜头选材。确有缺口的镜头写出需要补什么、可用的替代和是否阻塞。可选装饰缺失时直接简化。必讲的产品操作没有可验证画面时，明确缺口或安排标明为图解的解释。后续[素材阶段](./resources.md)补齐许可、实际使用的文件和入出点，沿用已有 ID。可先用同一份素材清单记录已知信息，之后原地补齐。

## 3. 先写叙事节拍，再写旁白和画面

先把故事排成观众能跟上的一串节拍。每节拍写明它回答什么问题、观众此时应该看到什么、靠哪条事实或哪份素材支撑。一个节拍可以拆成多个镜头。关键画面要在观众需要它的时候出现，复杂的命令、流程或画面给足观看时间。

| 片种 | 可用的叙事顺序 |
|---|---|
| 产品介绍 | 观众的问题 → 价值 → 真实操作与结果 → 下一步 |
| 口播讲解 | 问题 → 核心观点 → 具体例子或证据 → 总结 |
| 技术讲解 | 问题和前提 → 原理 → 操作和可见结果 → 适用边界 |

- **A 出镜口播**：以已核对的原声和 SRT 写分镜。标明哪段看到真人，哪段切到 B-roll、录屏或图解。需要时写出镜框的位置、形状与进出运动。画面被覆盖时保持原声连续。
- **B 真人讲解音频**：以原声和 SRT 组织画面。可用原视频画面作 B-roll，复用时静音辅助片段。由 AI 写画面与屏幕文字。A/B 要改说法或口播顺序时，另标补录或经同意重剪，听写保留原句。
- **C AI 起草旁白**：由 AI 写可直接朗读的正文和逐镜制作稿。先给出一稿及关键素材缺口，让用户审阅要说的话和主要画面。正文用口语、短语义句，按 [单行字幕](./captions.md) 预先分节，读一遍检查术语、节奏和停顿。从逐镜稿提取纯台词，按 [tone.md](./tone.md) 确认稿和样音后交 TTS，无需另外制作真人录制稿。

A/B 要新录时，先根据简报写台词和逐镜稿。补录时只为待录部分写新台词，保留已有原声的实际说法。未录段标「待录」，成片位置标「待对齐」。录制回传后，先确认实际使用的版本，再从成品主音轨生成或更新 SRT。已有真人素材中的口型只配与它匹配的原声。

## 4. 写成可直接制作的镜头清单

输出 `production/script.md`。文件开头放制作简报摘要、叙事顺序、不可删内容和素材缺口。按节拍分组，每个镜头有稳定编号（如 `S01`）。为实际台词段另编稳定 ID（如 `U01`），在稿内记录台词、说话人和锁音后核对的音轨相对区间。一个台词段可以覆盖多个镜头或字幕。可用小节或表格，保留以下字段。没有对应项写「无」或「延续上一镜」。

| 字段 | 每镜头写清什么 |
|---|---|
| 目的和来源 | 观众在此理解什么。事实引用 `Fxx` |
| 人声 | 出镜口播、真人旁白、TTS、保留的素材原声或无对白。注明说话人及台词段 ID，台词用逐字文本或核对后的原声。混合镜头区分谁在说与观众看见谁 |
| 成片位置 | 台词段 ID、成片起止和关键动作锚点。需要查字幕时可注明当前 SRT 的序号。无对白处写成片区间。还没拿到成品音轨时用「待对齐」，先记词句或动作锚点 |
| 素材和构图 | `Mxx`、对应源片段、裁切、前后层关系、出镜布局与主体焦点 |
| 动作和转场 | 开始状态 → 触发点 → 观众看到的结果。写从哪一镜怎样切入及原因。默认硬切，确有连续性需求时写转场方式、发生点和留出的重叠 |
| 屏幕文字 | 标题、提示、命令或代码的原文，写清位置及停留到何时。与旁白正文分开 |
| 音效和配乐 | 出现或收住的动作锚点、音效用途、与旁白的关系、配乐进出或压低位置。无需要时写「无」 |
| 动效或特效 | 要强调的对象、所用素材或图层、触发、动作和结束状态。写明是揭示信息、指示操作还是装饰，必要时指定关键画面留读时间 |
| 缺口与回退 | 缺失、许可待核实、要补录或要生成的内容，及保留原意的替代方案 |

### 示例镜头

下面是虚构的技术演示格式示例。实际项目用已核对的素材和来源。

> **S03 · 看清设置保存成功（F02）**
>
> 人声为真人旁白 U03「打开设置，保存更改。」画面从主持人硬切到录屏 M02，使用素材内 00:08–00:13，辅助录屏静音。旁白继续播放，画面留到保存提示消失后再切。
>
> 屏幕只显示录屏原有界面。点击「保存」时出现一圈高亮，收在成功提示出现前。点击声是候选，确认不会盖住关键词才使用。配乐延续并压低。录屏缺失时向用户要包含点击和结果的真实片段。

## 给录制者的口播稿

A/B 需要新录或补录时，在逐镜稿完成后另交 `production/recording-script.md`。已有原声足够时，直接按实际原声和 SRT 写逐镜稿。按**录制顺序**从 `production/script.md` 提取实际要说的话，保留制作稿版本和对应镜头 ID，方便对稿、补录和后期回填。同一段旁白覆盖多个镜头时只出现一次，可在段落标题标对应的镜头范围。

- 开头用几行写明整体语气、语速和专名读法。正文按可单独录制的短段组织，每段一小标题、一句一行。多人时标说话人；同一人连续讲解时省去重复标签。
- 台词与提示用不同格式。只在确实影响录制时另写「提示」，例如读法、停顿、重音，或出镜时必须执行的看镜头、等手势结束等动作。
- 制作信息留在逐镜稿里，包括素材路径、切镜和转场、构图、动画、特效、音效、配乐、SRT 及估算时码。只在画面出现的文字也留在逐镜稿里。录制者打开口播稿即可直接读。
- 台词改动先更新逐镜稿，再同步口播稿。交付前对照检查口播文字、顺序和段落 ID，避免同一段重复朗读或漏录。用户只要稿时，交两份稿就可以结束本轮。

录制稿示例：

> **第 03 段 · 保存设置（S03–S04）**
>
> 打开设置，点击保存。
>
> 看到成功提示，这一步就完成了。
>
> *录制提示（不念）：两句之间自然停顿。*

## 5. 锁音后补时间，交给制作

以成品音轨及 [时间映射](./timeline.md) 回填镜头区间。先照分镜约定，用 SRT 定位语义，再将台词段 ID 对到音轨上的实际区间。分镜留白处由 AI 根据上下文补编排，实际发音和画面事件决定精确落点。音效和转场不必和字幕同起同止。若关键动作的实际长度、字幕可读时间或成片目标冲突，先检查是否可以调镜头或给画面留停顿。调整人声内容或剪辑时回到工作流重算受影响的区间。

交稿前顺读一次旁白，再按逐镜稿从头走一遍，确认：

- 每项必讲内容有镜头承接。事实有来源，演示有已查看的真实素材或明确缺口。屏幕上的命令与例子完整。
- 每镜能找到素材和源片段，知道观众看到什么、听到谁、何时换画面。转场、特效和音效都有对象、触发点和结束状态。
- 字幕能按单行规则拆条，有足够的观看时间。多人、画面文字、旁白、操作声与配乐的优先级清楚。
- 正式区间覆盖片头、对白、停顿和片尾。素材和动画时长足以承接动作。按 [工作流](./workflow.md) 选一个能检验分镜的十五秒初剪窗口。
- 使用社区镜头卡或 SHOTBOOK 时，可在同一镜头条目引用其卡名。后续实现按官方或合用的社区 Remotion Skill 接入。

参考 [Adobe 制作前期指南](https://www.adobe.com/in/creativecloud/video/production.html) 和 [Adobe 拍摄脚本指南](https://www.adobe.com/au/creativecloud/video/discover/shooting-script.html) 对简报、脚本、分镜和镜头表的分工。这里用同一份逐镜制作稿贯穿配音、剪辑和 Remotion 实现。
