本文件是新片的第一阶段。续做时按工作流回到最早失效的交接物。它核对简报、素材和工具，分出硬停和建议。硬停没解除之前，不配音、不铺画面。建议写明之后就可以继续后面的阶段。

核对日期：2026-11-10。工具名单和许可以 [Video.md](../Video.md) 为准。这里不写 Remotion 组件，也不复制社区 Skill 的仓库。

## 硬停

继续做会编出实质内容，或会越界时，立刻停下，列出缺的项，等用户补上。

只包括：

- 形态 A、B、C 两可，或互相冲突
- A/B 要用已有原声却拿不到源文件时，暂停转写与对齐。已确定要新录或补录时，先写制作稿和录制稿
- C 缺少可确定的主题或制作目标，或用户要求保留原稿却未提供
- 已经要使用的素材许可不清，或和商用冲突
- 下一步会改变音色、形态、付费或云端工具、许可敏感的素材

不要编造产品、音色、经历或没给过的媒体。缺的截图不要画成界面。缺的出镜不要用素材库里的人代替。

下面这些不硬停。写进准备结论，用户否定再改：

- 未提供通用音效、配乐、动画、特效等素材时，按 [resources.md](./resources.md#通用素材的选用顺序) 复用合用资源。

- 语言：简报里已经能看出就采用看出的语言
- 画幅：建议 1920×1080，或简报里的平台默认。写明建议，不静默改成另一个尺寸
- 字体：没点名时建议 Video.md 第 7 节的 Noto CJK。点名的文件不在时，问是要文件还是改用这项建议，不静默替换
- 片种：简报清楚就写上。又像产品介绍又像口播时，记成混合片并继续，不要为了凑成唯一标签停下
- 社区 Skill：按 [workflow.md](./workflow.md) 的「画面」推荐最合适的一个。用户拒绝或当时没有，用官方 Remotion skills 和工程或其他可用资源继续

只读检查可以做：路径是否存在、技能列表里有什么、本机是否听得到 AudioSmith。安装、下载模型、克隆、删除、脚手架和正式导出，先把命令给用户看，同意后再执行。预览和短样片的同意范围见 workflow「命令要不要再问」。

## 先确认形态

三种形态互斥。开工回复里写明是哪一种。用户已经说清就不要再问一遍，但要把判定写出来。判不清就停。

| 形态 | 含义 | SRT 从哪来 |
|---|---|---|
| A 真人出镜视频 | 已有或计划拍摄真人口播，成片里会使用其出镜画面 | 与画面一致的那条人声。做法在 [tone.md](./tone.md) |
| B 真人讲解音频 | 已有或计划录制真人讲解，成片不安排出镜表演。人声可来自音频文件或视频音轨 | 这条讲解的人声。做法在 [tone.md](./tone.md) |
| C 无真人主音轨 | 没有指定的真人口播或出镜表演。AI 可按主题、素材和需求起草 | 确认稿和样音后的 TTS 成品音轨 |

片种不是形态。产品介绍、口播讲解、技术讲解都可以是 A、B 或 C，也可以在一支片子里同时出现。画面工具不由片种单独决定。

判定：

- 用户明确要新录或补录时，按成片是否使用出镜画面判为 A 或 B，无需等文件才能定形态。
- 用户给了出镜表演，要在成片里出现这个人：A。产品介绍加上这个人，仍然是 A，产品镜头和出镜布局可以各选工具。
- 用户写「只有真人讲解视频」：按 B。若画面明显是人对着镜头讲，和这句话冲突，停下来问。
- 同时有出镜视频和另一条讲解音频：优先 A。SRT 只用和画面一致的那条人声。不能确定哪一条跟画面一致，停下来问。
- 既有稿又有真人录音：不是 C。录音对得上出镜表演就是 A，否则是 B。稿只用来校对听写。
- 用户要做片，只给了话题、目标或素材：能确定主题且没有真人录制计划或可用原声时，标为 C，由 AI 按 [script.md](./script.md) 起草并交审。只有不能确定主题或用户明确要求保留原稿却没给时，才为脚本停下。
- 以上都无法归入一条：停下来问。

出镜镜头的形状、位置和运动到 [script.md](./script.md) 写成建议，交给用户看。不在这里选定，也不默认圆形或画中画。形态确认之后不要自动改成另一种。

## 检查清单

硬停行未就绪，就停。建议行写成「建议」或「就绪」，不因为还没亲口确认而停掉整轮。

| 项 | 怎么核对 | 结论 |
|---|---|---|
| 形态 | 用上一节归类 | 硬停：不是唯一的 A、B 或 C |
| A 的成片 / B 的声音 | 核对已有路径或录制计划 | 有录制计划时先交录制稿，转写与对齐等实际素材。计划使用现有文件但读不到时，先补源文件 |
| C 的稿 | 确定主题、目标和 AI 可利用的输入 | 用户无需写稿。主题不明确或指定使用的原稿缺失时，问最少的澄清问题 |
| 许可 | 已要使用的第三方文件有没有许可 | 硬停：不清，或商用片上的 CC BY-NC。这条不进画面 |
| 音色 | 形态 C 合成前才需要 | 不在准备阶段硬停。没有方向时，合成前问。不替他选定，也不自动改去 Edge TTS |
| 语言 | 看简报 | 建议：采用能看出的语言，写明 |
| 画幅 | 看简报或平台 | 建议：1920×1080，或平台默认。写明 |
| 片种 | 看简报在讲产品、口播还是技术 | 建议：清楚就记下。混合就写混合，并列出各段主要看什么 |
| 字体 | 点名的文件是否存在 | 建议：没点名用 Noto CJK。点名的文件缺失就问，不静默替换 |
| 事实 | 产品名、地址或文件能否指回用户 | 没有可指的产品却要介绍该产品：硬停，不编一个。其余缺口记在脚本里 |
| 识别 | 留到 [tone.md](./tone.md) | 准备阶段不因为 whisper 或 AudioSmith 还没试过就停下。两条都失败、又要写 SRT 时才停 |
| AudioSmith | 仅当会话在主人的 Mac 上时访问 `GET http://127.0.0.1:3901/health`。端口以应用为准 | 远程会话不连接 `127.0.0.1`。说明够不到。形态 C 要合成时再问换机器或 Edge TTS |
| 官方 Remotion skills | 技能列表里有没有创建、markup、Studio、渲染、字幕。目录名以安装结果为准 | 要做画面还没有时，给出 `npx skills add remotion-dev/skills`，同意后再装。写脚本不必等它 |
| 社区 Skill | 按这部片子主要看的东西，看 video-shotcraft 或 video-talkcraft 是否已安装 | 建议安装最合适的一个，命令在下面。没装或用户拒绝：官方 skills，写入 `production/paths.md` |
| 渲染工具链 | 用户指出的工程里有没有 Remotion | 没有工程时，脚手架先问。新环境或素材类型有变时，走下面的「建项与最小试渲」 |
| 演示素材 | 路径或页面当时是否打得开 | 缺的记成缺口。不画假界面，也不为此停掉整轮 |
| 风格仓库 | 不开工就逐个安装 | 自家样式即可。用户点名某一个时，只核对那一个能否打开 |
| 帧率 | 看工程或简报 | 未指定不挡住。新建工程用 30 fps。用户另有帧率就改 |

社区 Skill 的安装命令，只在推荐并且用户同意后执行：

```bash
npx skills add Vincentwei1021/video-shotcraft
npx skills add Vincentwei1021/video-talkcraft
```

安装依赖若因网络停下，再问是否按 Smartpigai 文章里的做法使用国内镜像。镜像不是默认步骤。

## 建项与最小试渲

要独立验证这套规则时，运行仓库的 [SyncSmoke 试片](./examples/sync-smoke/README.md)。现有工程按下面的清单核对自己的真实素材。

使用已有视频工程时，先记录包管理器、锁文件、入口与 composition ID。新建时，用户同意后可以按[官方建项说明](https://www.remotion.dev/docs/ai/coding-agents)执行 `npx create-video --yes --blank my-video`，在视频工程内工作。保留锁文件，复跑用对应包管理器的锁文件安装方式，例如 npm 的 `npm ci`。用 `npx remotion versions` 核对 `remotion` 与项目中安装的 `@remotion/*` 使用相同的精确版本。已有项目沿用其入口和渲染设置。

第一次走这条链路时，用获准使用的短录音和一段真实录屏试渲。新建测试 composition 可叫 `SyncSmoke`，保留两句对白和一句间停顿。用一小段独立片头验证偏移，录屏在第一句出现并跨过停顿，第二句时仍可见。也可以在现有 composition 里选符合这些条件的窗口。

1. 将主音轨、录屏和用于渲染的 SRT 放在工程可读取的位置。默认将 `production/narration.srt` 原样复制到 `public/narration.srt`，每次源 SRT 更新后同步，避免预览使用旧副本。用 `staticFile()` 加载本地媒体和字幕，以 `@remotion/captions` 的 `parseSrt()` 解析字幕，并等加载结束再渲染。按 [timeline.md](./timeline.md) 放置各轨，辅助录屏静音。
2. 运行 `npx remotion studio --no-open`，打开终端实际输出的 URL，选该 composition。核对片头没有提前出声或出字幕，第一句与第二句分别对齐，停顿里无字幕但演示连续。确认需要的字体已加载。
3. 在同一工程用同一 composition 和 props 试渲。以 30 fps、2 秒片头、音轨 10～15 秒的窗口为例，先确认 composition 覆盖这个区间，再执行 `npx remotion render SyncSmoke out/sync-smoke-v01.mp4 --codec=h264 --frames=360-509 --overwrite=false`。实际测试用所选窗口换算后的帧范围。
4. 播放导出文件，对照 Studio 的同一段，检查旁白、字幕、录屏、首尾帧和有无双声。这个示例应为 150 帧、约 5 秒。可用 `ffprobe` 核对帧数和音视频流。把命令、版本、composition ID、props（若有）、输出和结果写进 `production/paths.md`。失败先排查素材可读性、字幕版本、浏览器和依赖。用户的十五秒初剪另按 [workflow.md](./workflow.md) 制作。

准备时同时确定交付规格。记录平台或用途、画幅、帧率、目标时长、容器与编码，以及字幕是烧录、单独交付还是两者都要。无明确平台规格时，可建议 MP4、H.264 视频、AAC 音频，沿用工程画幅和帧率。字幕预先按 [单行字幕](./captions.md) 确定字数上限和安全区。具体导出检查见 [quality.md](./quality.md)。

## 准备阶段的产出

在回复里留下硬停和建议。视频工程已经存在时，把同一份结论写到 `production/readiness.md`，不要写进 SkillsPocket。

通过的标准：没有未解除的硬停。形态 C 通过准备，仍然不表示可以合成全长。

准备通过之后，按 [script.md](./script.md) 写一份短调研简报。形态 C 在写旁白之前写。形态 A、B 有可用成品原声时先做 SRT，简报不挡转写。需要新录或补录时，先写简报和稿，回传后再做 SRT。语言、画幅、字体和社区 Skill 仍按上面的建议，不因为要调研而重新变成硬停。
