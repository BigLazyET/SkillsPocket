# 脚本

[入口](./SKILL.md) · [编排](./produce-prompt.md) · [工作流](./workflow.md) · [准备](./preparation.md) · [脚本](./script.md) · [音色](./tone.md) · [素材](./resources.md) · [音效](./sfx.md) · [质量门](./quality.md)

本文件规定制作脚本怎么写、怎么验收。它不生成语音，也不写 Remotion 场景代码。顺序和停止条件在 [workflow.md](./workflow.md)。主语音时间轴的生成在 [tone.md](./tone.md)。

核对日期：2026-11-10。

## 输入

准备阶段确认过的形态、片种、语言、画幅，以及用户给出的事实。

- A、B：已经核对过的 `production/speech-timeline.srt`。旁白正文是听写，不是另写的一篇稿。
- C：用户的脚本或要点。这一步先写要说的话和画面意图，时间列先空着。全长合成并得到时间轴之后，再把时间填上。

用户的经历和产品数据，只使用用户提供的内容。公开产品以用户给的地址、仓库或文件为准。页面上没有的功能不要写进旁白。条件不够就停下来问，不要编镜头去填。

## 三层，分开写

| 层 | 内容 | 交给后阶段的约定 |
|---|---|---|
| 人声文本 | A、B 是时间轴里听到的话。C 是要念的话 | C 的这一层才送进 [tone.md](./tone.md)。标记、屏幕说明和素材备注先去掉 |
| 屏幕文字 | 人声不念、但画面上必须完整出现的提示、命令、示例 | 标明「仅屏幕展示」。不要压成几个要点 |
| 素材与动作 | 该段可用的截图、录屏、图表 | 时间必须落在时间轴的某一段上。没有时间轴时，C 只写意图，不写秒数 |

## 三种段落骨架

骨架是叙事顺序，不是镜头清单，也不是媒体清单。短视频可以落成大约 6～8 段，这是 Smartpigai 文章里的短片起草习惯，不是长片的上限。长片按章节写。某一拍没有用户给的素材，就写「缺口」并停在该拍，不要发明一个镜头。

| 片种 | 段落顺序 | 画面倾向 |
|---|---|---|
| 产品介绍 | 痛点 → 卖点 → 真实演示 → 行动引导 | 演示段用真实截图或录屏 |
| 口播讲解 | 问题 → 观点 → 例子 → 总结 | 形态 A 才出现出镜的人。B 和 C 用字幕和图形 |
| 技术讲解 | 问题 → 原理 → 操作演示 → 适用边界 | 原理用图解。操作演示用录屏或截图。边界要写出不适用于什么 |

片种不改变 [workflow.md](./workflow.md) 里三种形态的顺序。

## 脚本里至少有的列

| 列 | 要求 |
|---|---|
| 段落 | 编号 |
| 人声文本 | A、B 与时间轴原文一致。C 只含要念的话 |
| 时间轴 | 引用 `speech-timeline.srt` 的序号或起止。C 在时间轴出现之前写「待合成」 |
| 屏幕文字 | 没有则写「无」 |
| 画面意图 | 观众这一段看见的那一件事。一句。不写 React |
| 素材 | 路径、待补，或「图解」 |
| 备注 | 必做的动作、不可删的句子、许可问题 |

画面时间不得超出它引用的那一条人声的起止，除非是简报里约定的片头或片尾。不要按字数另估一套秒数。

### 形态 A 还要记下出镜布局

这些是必须做出的决定，不是组件实现。用户没选，就列出选项问他，不要默认。

| 决定 | 要写清什么 |
|---|---|
| 形状 | 例如圆形、圆角矩形、铺满画幅，或用户给出的其他形状 |
| 位置 | 在画布上的区域。不要只写「好看」 |
| 运动 | 例如保持、缩小、放大、进入或离开画中画。写它对应的时间轴序号 |

同一时刻只安排一种出镜布局。B-roll 盖住出镜时，人声仍用这条时间轴，不换轨。

不分析嘴型，也不为对口型加第二条声音。

### 形态 B

不要加出镜布局。讲解若来自视频文件，那个画面不写成主持人镜头。文件里的画面若要当 B-roll，按普通素材写路径，并在 [resources.md](./resources.md) 里静音其解说。

### 形态 C

确认稿之前，时间列保持「待合成」。用户确认的是要说的话和画面意图，不是秒数。

时间轴写好之后，只补时间列和因此需要改的画面段落。不要改已经确认的人声文本，除非用户要求改稿；改稿就要重新确认，并重做受影响的合成。

## 时长

成片长度跟随主语音时间轴，另加约定的片头片尾。

「大约 N 秒」只约束 C 的写稿量级。合成后差得明显，回到改段落，不要拉画面来凑。

「必须正好 N 秒」要标成硬约束。用时间拉伸去卡秒之前先问用户。

## 画面意图的限度

可以写「这一句的时间里切到设置页的录屏」。不要写一段 React。

同一支片子先定背景、字体和信息层级。转场要帮助这句话被看懂。

产品界面用真实画面。只有 [resources.md](./resources.md) 允许时才标「代码绘制界面」，并写明用户已接受。图解标成「图解」，不要标成截图。

## 验收

- 每一段画面要么引用时间轴的一条，要么是约定的片头片尾，要么在 C 的合成前标成「待合成」。没有第四种时间。
- A、B 的人声文本没有被改写成没说过的句子。
- C 送去合成的文本没有屏幕说明和素材备注。
- 必讲的命令和示例完整保留。
- 演示段有真实素材或明确缺口。缺口没有被改成代码绘制或编出来的镜头。
- A 的形状、位置、运动都有用户的决定，并各自对应时间轴序号。
- B、C 没有出镜表演布局。
- 没有用户没提供的经历和产品数据。

## 失败时

| 现象 | 处理 |
|---|---|
| 没有时间轴却要写 A、B 的画面秒数 | 回到 [tone.md](./tone.md)。不估时 |
| 事实或素材不够 | 停下问。不编产品，不编镜头 |
| 形态 A 没有布局决定 | 停下问形状、位置和运动 |
| 用户否定结构 | 只改他指出的段落。C 若改了人声，作废受影响的时间轴 |
| 稿已确认后又改了要念的句子 | 从 [tone.md](./tone.md) 重做受影响的合成和时间轴 |
