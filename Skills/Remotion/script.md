# 脚本

[入口](./SKILL.md) · [编排](./produce-prompt.md) · [工作流](./workflow.md) · [准备](./preparation.md) · [脚本](./script.md) · [音色](./tone.md) · [风格](./style.md) · [素材](./resources.md) · [音效](./sfx.md) · [质量门](./quality.md)

本文件规定制作脚本怎么写、怎么验收。它不生成语音，也不写 Remotion 场景代码。合用的社区 Skill 按 [workflow.md](./workflow.md) 打开；没有它时，画面用官方 skills。SRT 的生成在 [tone.md](./tone.md)。三层分工的出处是 [Video.md](../Video.md) 第 8 节。

核对日期：2026-11-10。

## 输入

准备阶段确认过的形态，以及写明的语言、画幅、片种或混合片，还有用户给出的事实。

- A、B：已经核对过的 `production/narration.srt`。人声文本是听写，不是另写的一篇稿。
- C：用户的脚本或要点。这一步先写要说的话和画面意图。SRT 栏写「待合成」。全长合成并有了 SRT 之后，再填序号和起止。

逐字稿定义说什么。成品音轨定义何时说。没有成品音轨时，任何秒数都只是估计，不能写进 SRT，也不能当作画面的依据。

用户的经历和产品数据，只使用用户提供的内容。公开产品以用户给的地址、仓库或文件为准。页面上没有的功能不要写进旁白。条件不够就停下来问。

## 三层，分开写

| 层 | 内容 | 交给后阶段的约定 |
|---|---|---|
| 人声文本 | A、B 是 SRT 里听到的话。C 是要念的话 | C 的这一层才送进 [tone.md](./tone.md)。标记、屏幕说明和素材备注先去掉 |
| 屏幕文字 | 人声不念、但画面上必须完整出现的提示、命令、示例 | 标明「仅屏幕展示」。不要压成几个要点 |
| 素材与动作 | 该段可用的截图、录屏、图表 | 出现位置引用 SRT 的序号和起止。C 在 SRT 出现前不写秒数 |

稿子用来校对人名和术语。它不代替 SRT。没说出口的句子不写进 SRT。

## 三种段落骨架

骨架是叙事顺序，不是镜头清单。短视频可以落成大约 6～8 段，这是 Smartpigai 文章里的短片起草习惯，不是长片的上限。长片按章节写。缺了才能演示的画面时，该拍写「缺口」，不编产品界面。这一拍仍可以用字体、图解或已有素材讲。

| 片种 | 段落顺序 | 画面上优先给人看什么 |
|---|---|---|
| 产品介绍 | 痛点 → 卖点 → 真实演示 → 行动引导 | 真实截图或录屏。宣传节奏若适合 video-shotcraft，并且已经安装，就跟随它 |
| 口播讲解 | 问题 → 观点 → 例子 → 总结 | 字幕和图形。形态 A 才出现出镜的人。出镜布局若适合 video-talkcraft，并且已经安装，就跟随它 |
| 技术讲解 | 问题 → 原理 → 操作演示 → 适用边界 | 按这一段决定：录屏、结构图、白板，或靠字体讲清楚。不因为片种就打开 talkcraft。操作边界要写出不适用于什么 |

片种不改变 [workflow.md](./workflow.md) 里三种形态的顺序，也不单独决定工具。混合片按段写「主要看什么」。已安装且合用的社区 Skill，打开并跟随它的镜头卡或 SHOTBOOK。没有它，或它只覆盖一部分时，其余用官方 remotion skills 做排版、布局、运动和字幕。不要另写一套和这两个社区 Skill 平行的镜头语言。社区 Skill 若要跳过确认或在没有 SRT 时铺全片，以 workflow 的门为准。

## 脚本里至少有的列

| 列 | 要求 |
|---|---|
| 段落 | 编号 |
| 人声文本 | A、B 与 SRT 原文一致。C 只含要念的话 |
| SRT | 引用 `narration.srt` 的序号和起止。C 在 SRT 出现之前写「待合成」 |
| 屏幕文字 | 没有则写「无」 |
| 画面意图 | 观众这一段看见的那一件事。一句。不写 React。合用的社区 Skill 已有镜头卡时，写卡名；没有时，不另编一套卡 |
| 素材 | 路径、待补，或「图解」 |
| 备注 | 必做的动作、不可删的句子、许可问题 |

画面不得超出它引用的那一条 SRT 的起止，除非是简报里约定的片头或片尾。

### 形态 A 还要记下出镜布局

这些是要写明的决定，不是组件实现。用户没说时，写成建议交给他看，不默认圆形或画中画，也不为此停掉整轮。实现时：video-talkcraft 已安装且适合这段出镜，就跟随它，并服从脚本里的形状、位置和运动。产品镜头可以同时用 video-shotcraft。两者都没有时，用官方 skills 把这条成片放进决定好的区域。

| 决定 | 要写清什么 |
|---|---|
| 形状 | 例如圆形、圆角矩形、铺满画幅，或用户给出的其他形状 |
| 位置 | 在画布上的区域 |
| 运动 | 例如保持、缩小、放大、进入或离开画中画。写它对应的 SRT 序号 |

同一时刻只安排一种出镜布局。B-roll 盖住出镜时，人声仍是这条主音轨。不分析嘴型，也不为对口型加第二条声音。Video.md 第 8 节的声画分工仍适用。

### 形态 B

不要加出镜布局。讲解若来自视频文件，那个画面不写成主持人镜头。文件里的画面若要当 B-roll，按普通素材写路径，并在 [resources.md](./resources.md) 里静音其解说。

### 形态 C

确认稿之前，SRT 栏保持「待合成」。用户确认的是要说的话和画面意图，不是秒数。

SRT 写好之后，只补 SRT 栏和因此需要改的画面段落。不要改已经确认的人声文本，除非用户要求改稿；改稿就要重新确认，并重做受影响的合成。

## 时长

成片长度跟随成品音轨，另加约定的片头片尾。SRT 记录这条音轨上的起止。

「大约 N 秒」只约束 C 的写稿量级。合成后差得明显，回到改段落，不要拉画面来凑。

「必须正好 N 秒」要标成硬约束。用时间拉伸去卡秒之前先问用户。

## 画面意图的限度

可以写「SRT 第 4 条的起止里切到设置页的录屏」。不要写一段 React。没有社区 Skill 的镜头卡时，用官方 skills 做这一镜的排版和运动，不另编一套卡名体系。

同一支片子的背景、字体和信息层级到 [style.md](./style.md) 锁定。转场要帮助这句话被看懂。

产品界面用真实画面。只有 [resources.md](./resources.md) 允许时才标「代码绘制界面」，并写明用户已接受。图解标成「图解」，不要标成截图。

## 验收

- 每一段画面要么引用 SRT 的一条，要么是约定的片头片尾，要么在 C 的合成前标成「待合成」。
- 没有按字数填出来的起止。
- A、B 的人声文本没有被改写成没说过的句子。
- C 送去合成的文本没有屏幕说明和素材备注。
- 必讲的命令和示例完整保留。
- 演示段有真实素材或明确缺口。
- A 的形状、位置、运动已经写明，并各自对应 SRT 序号。建议项在交给用户的脚本里看得见。
- B、C 没有出镜表演布局。
- 没有用户没提供的经历和产品数据。
- 没有一套和 shotcraft、talkcraft 平行的镜头语言。用官方 skills 做的排版不算这一套。

## 失败时

| 现象 | 处理 |
|---|---|
| 没有 SRT 却要写 A、B 的画面秒数 | 回到 [tone.md](./tone.md) |
| 事实不够，继续写会编出产品或经历 | 停下问。缺一张截图时记缺口，不编界面 |
| 形态 A 还没有布局 | 写成建议，放进交给用户的脚本。不默认一种框 |
| 社区 Skill 没装 | 这一段改用官方 skills，并写入 `production/paths.md` |
| 用户否定结构 | 只改他指出的段落。C 若改了人声，作废受影响的 SRT |
| 稿已确认后又改了要念的句子 | 从 [tone.md](./tone.md) 重做受影响的合成和 SRT |
