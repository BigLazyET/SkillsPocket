# 素材

[入口](./SKILL.md) · [编排](./produce-prompt.md) · [工作流](./workflow.md) · [准备](./preparation.md) · [脚本](./script.md) · [音色](./tone.md) · [风格](./style.md) · [素材](./resources.md) · [音效](./sfx.md) · [质量门](./quality.md)

本文件规定画面素材怎么收集、怎么交到一个 SRT 条目。图标、字体、插画、录屏工具和 B-roll 站点的名单与许可以 [Video.md](../Video.md) 第 6 节和第 7 节为准，这里不重列整张表。音效见 [sfx.md](./sfx.md)。配音见 [tone.md](./tone.md)。

核对日期：2026-11-10。

## 输入和输出

输入是制作脚本、已核对的 `production/narration.srt`，以及用户给出的文件夹或网址。入点和出点是这条 SRT 上的起止，或录屏文件内部的片段。没有 SRT 时，只列路径和许可，不写进成片的秒数。

输出是视频工程里的素材清单。每条至少有：

| 列 | 要求 |
|---|---|
| 路径 | 相对视频工程。composition 实际加载的路径若不同，两处都写 |
| 种类 | 截图、录屏、出镜、图解、图标、字体、动效、生成图、代码绘制界面 |
| SRT | 对应 `narration.srt` 的序号。一段可以有多条 |
| 素材内片段 | 录屏和出镜成片要有。静图写「整幅」 |
| 来源 | URL 和抓取日期，或「用户提供」 |
| 作者、许可、署名 | 未知就写「待确认」，并且不进画面 |
| 自带声音 | 保留、静音，或只留操作声。辅助录屏的解说默认静音 |
| 实际路径 | 降级后真正用的那一个来源，与 `production/paths.md` 一致 |

第三方许可要求署名时，把署名句子集中到一处。没有需要署名的素材时，不要为了凑片尾去写一份署名。

## 收集顺序

1. 用户已经放进工程或指明路径的文件。
2. 产品自己的界面：打开简报里的真实站点、应用或仓库，截图或用 Video.md 第 7 节的 OBS 录屏。打不开就向用户要文件。
3. 官方品牌包、官方截图、用户自己的角色和透明动画。
4. 图标、插画和动效点缀：按下面的降级顺序，名单只读 Video.md 第 6 节。
5. 图解。技术结构图用 Video.md 第 7 节的 Anatomy。它产出的是图，不是已经对好 SRT 的视频。
6. 用户同意的生成图。标明生成工具，不要把它写成产品照片。
7. 代码绘制的产品界面。只在上面几步都没有，并且用户明确接受时使用。

查找和重命名可以由 Agent 做。不要用无关画面填空。游戏或像素风的点缀，用仓库里的 [scenario-pixel-vfx](../VFX/scenario-pixel-vfx/SKILL.md)，按整数倍缩放。

## 降级顺序

把失败原因和实际使用的来源写入 `production/paths.md`。许可不清、需要署名而本片不能署名、或商用片上的 CC BY-NC，跳过该条并记下。付费或条款未核清的来源先问，不自动用。全部允许的来源都没有这张图时，停下来问，不画一个假界面。

| 需要 | 顺序 |
|---|---|
| 品牌标志 | Lobe Icons，没有再用 Simple Icons。要官方高清时先看 Brandfetch 的条款，条款不清就问 |
| UI 小图标 | Lucide，没有再用 Tabler。需要线宽或填充变体时用 Phosphor 或 Heroicons。搜索用 Iconify，子库许可仍按 Video.md |
| 动效点缀 | LottieFiles，逐条看授权。这一条许可不清就换下一条，不换来源类别去冒充 |
| 场景插画 | Neu Icons、Twemoji、unDraw，按 Video.md 是否需要署名。Storyset 一类常要署名，写进清单 |
| 字体 | 用户点名的文件。文件缺失就问。没点名时，询问是否使用 Video.md 第 7 节的 Noto CJK，同意前不下载。不自动换一款别的字体 |
| 产品画面 | 用户的文件，然后是当时打得开的真实页面或 OBS 录屏。站点打不开就向用户要文件 |
| 空镜和封面 | Pexels、Mixkit，按它们各自的许可，不标成 CC0 |
| 结构图 | Anatomy。它失败时向用户要图，或在他同意后做一张标明「图解」的示意图 |
| 像素点缀 | 仓库内 scenario-pixel-vfx |

## 真实界面

产品介绍和技术讲解的演示段，默认是截图、录屏或官方素材。video-shotcraft 已安装且这段是产品界面时，优先跟随它的采集。video-talkcraft 已安装且这段要证据截图时，优先跟随它。都没有时，用上面的顺序和 Video.md 第 7 节的 OBS。缺文件就记缺口，向用户要，不画假界面。

代码绘制界面时，清单的种类写成「代码绘制界面」，备注写明用户已接受。观众会把它看成真实产品时，画面或旁白里说明这是示意。[Launch Video on X](https://www.remotion.dev/prompts/launch-video-on-x) 用代码画界面，本文件不把它当成默认。

OBS 是工具，不是 Skill。录屏里的解说默认不进成片。

## 命名

文件名使用小写英文、数字和连字符：`{种类}-{内容}-{来源简称}.{ext}`。种类用 `shot`、`screen`、`presenter`、`icon`、`font`、`mg`、`diagram`。不要用 `final`、`new`、`222`。

Remotion 要读取的文件放到工程的 `public/`，或官方 Skill 要求的位置。

## 透明通道和角色

用户已有的角色小动画优先复用。带 Alpha 的视频要验证这条渲染链保留透明。Video.md 记录的示例是 HEVC（Alpha）。普通 H.264 MP4 不能当成透明素材。验证失败就改用该链支持的格式或 PNG 序列。抠像只对有权处理的素材做。

## 交到段落

- 用 SRT 序号对上制作脚本。
- 录屏使用素材内片段，不把整段原始文件铺进一个短句。
- 形态 A 的出镜镜头用脚本里已经决定的形状、位置和运动。B-roll 盖住脸时，人声仍是那条主音轨。
- 形态 B、C 不把素材框成出镜表演。
- 图解放在它解释的那一条 SRT 的起止里。
- 清单没有的画面，先补清单再进工程。

## 失败时

| 现象 | 处理 |
|---|---|
| 站点打不开或需要登录 | 向用户要截图或录屏 |
| 只有低分辨率官方图 | 在清单写明尺寸。放大到模糊就换素材 |
| 许可冲突 | 从画面拿掉，换一条许可清楚的，或请用户决定 |
| 透明素材在预览里变成黑底 | 标成未通过，换格式后再用 |
