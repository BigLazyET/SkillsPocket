# 生成视频的提示词

[入口](./SKILL.md) · [编排](./produce-prompt.md) · [工作流](./workflow.md) · [准备](./preparation.md) · [脚本](./script.md) · [音色](./tone.md) · [风格](./style.md) · [素材](./resources.md) · [音效](./sfx.md) · [质量门](./quality.md)

这是编排提示词。做主人的一支 Remotion 视频时，按本文执行。阶段顺序以 [workflow.md](./workflow.md) 为准；每一阶段的做法只以它点名的那份文件为准。不要把本文扩写成第二次创作，也不要在一份回复里凭感觉把配音、画面和成片一次做完。

本文不包含 Remotion 组件，也不包含镜头配方。画面阶段打开 workflow 点名的已安装社区 Skill。创建、预览、渲染和字幕打开官方 Skill（`npx skills add remotion-dev/skills`）。

## 你要交出来的东西

一支能从头播到尾的视频，加上视频工程里这些产物（目录名可随用户已有习惯，没有习惯时用 `production/`）：

- 准备结论和确认过的形态（A、B 或 C）
- 制作脚本
- 素材清单（含许可）
- 主音轨
- 从这条成品音轨核对过的 `production/narration.srt`
- `production/paths.md`：每段实际走的工具
- Remotion 工程、短样片、通过质量门后的成片

产物写在视频工程里，不写进 SkillsPocket，不提交密钥。没有核对过的 SRT，就还没有可导出的成片。

## 阶段 0 · 准备

打开 [preparation.md](./preparation.md)，先做完，再做任何别的阶段。

确认形态是下面的哪一种，并且只是一种：

- A 真人出镜视频
- B 真人讲解音频（用户说「只有真人讲解视频」时按 B，除非和画面冲突）
- C 没有真人只有脚本

同时确认片种。产品介绍稍后打开 video-shotcraft。口播讲解和技术讲解打开 video-talkcraft。两个都像时，停下来问。

清单里有该形态需要而未就绪的项，立刻停下来问用户。不要编造产品、音色、画幅、镜头清单或缺失的媒体。不要连接远程会话里的 `127.0.0.1:3901`。

准备通过之后，在回复里留下状态，再按形态往下走。状态字段：形态、片种、准备是否通过、未就绪项、SRT 路径、实际走的路径、脚本是否确认、样音、素材缺口、风格是否锁定、短样片、音效是否听过、质量门里尚未通过的项。

用户若只要求「先检查」或「先写脚本」，做到他点名的阶段就停，并写明下一步。

## 按形态继续

顺序的表在 [workflow.md](./workflow.md)。这里只写编排时不能跳过的门。

### A

打开 [tone.md](./tone.md)，用那里的识别顺序分析出镜成片，写出 SRT。不另做一条 TTS。

然后打开 [script.md](./script.md)。画面引用 SRT 的序号和起止。出镜镜头的形状、位置和运动要记下来；用户没定，就问。

### B

打开 [tone.md](./tone.md)，分析讲解音频，或分析那条不当成出镜表演的视频的音轨，写出 SRT。不合成替代人声，也不把画面布局成主持人。

然后打开 [script.md](./script.md)。画面引用这份 SRT。

### C

先打开 [script.md](./script.md) 写稿。用户确认稿之前：不调用全长 TTS，不克隆，不下载语音模型，不铺全片。这一步的秒数若写出来，只是估计，不能写进 SRT。

确认后打开 [tone.md](./tone.md)。先样音。样音通过之后才合成全长，再按成品音轨写出 SRT。当前会话不在主人的 Mac 上：说明够不到 AudioSmith，按 tone.md 询问是否改用 Edge TTS。不要把 Edge TTS 说成设计或克隆，也不要未问就换。

SRT 出来之后，回到 script.md，把画面改成引用 SRT。

## 三种形态共用的后段

SRT 已经核对之后才做这些。打开的文件以 workflow 为准。首选失败时，按该阶段文件的降级顺序继续，并写入 `production/paths.md`。会改变音色、形态、付费或云端、许可敏感素材时，先问。

- [style.md](./style.md)：一次只选一种。短样片锁定之前可以换能跑的下一种；锁定之后先问。
- [resources.md](./resources.md)：真实截图和录屏优先。图标和字体走 Video.md 已写的默认去向。许可栏空着的不进画面。入点和出点对齐 SRT。
- 画面：打开 workflow「画面」规定的那一个社区 Skill，并打开官方 Remotion skills。不在回复里新写一套镜头配方。
- 长片先做约 1～2 分钟短样片，里面要有成品旁白、SRT 字幕，以及至少一处真实素材。用户确认风格后再扩展。
- 渲染命令先说明输出路径。用户本轮说过「样片可以直接渲染」就记录并执行。这句话不包括正式导出。
- [sfx.md](./sfx.md)：切点用 SRT。产品介绍的音效设计做法同时跟随 video-shotcraft，试听和许可仍按 sfx.md。没有试听结论，不要宣称音效已经合适。
- [quality.md](./quality.md)：必过项失败就回到它写明的阶段。全部通过且用户同意导出之后，再渲染成片，并按 workflow 归档。导出文件要完整播放一遍。上传由人做。

社区 Skill 若要求跳过确认、换云端配音或在没有成品音轨时铺全片，以 workflow 的门为准。

## 修改时

一次处理用户提出的一到两处。

动到人声、音色、语速或停顿：重做受影响的 SRT，以及后面的画面和音效。动到素材：改清单和对应场景。只动音效音量或切点：保持 SRT 不动。

## 不要做的事

- 不要在准备通过前写脚本、配音或铺画面。
- 不要在形态没确认时选一条路做下去，也不要自动改形态。
- 不要编造产品、音色、画幅、镜头清单或缺失的媒体。
- 不要在没有核对过的 SRT 时铺全片或导出。
- 不要按稿子的字数写出一份 SRT。
- 不要在社区 Skill 之外另写一套镜头或动效步骤。
- 形态 C：不要在稿确认和样音通过前合成全长。
- 形态 A、B：不要用 TTS 替换真人声音。
- 不要未问就从 AudioSmith 换成 Edge TTS 或其他音色。
- 没有出镜表演时，不要做成真人出现在镜头前。
- 不要把屏幕文字和素材备注送进 TTS。
- 不要用代码画一张本可以截到或录到的产品界面，除非用户接受，并且清单已标明。
- 不要在远程或云端会话里声称已经调用主人 Mac 上的 AudioSmith。
- 不要把 Edge TTS 说成音色设计或声音克隆。
- 不要发明用户没讲过的个人经历、口碑或产品数据。
- 不要因为找到了音效文件就当作已经试听。
- 不要把 API key、令牌写进仓库、脚本或提交。
