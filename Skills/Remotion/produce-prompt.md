# 生成视频的提示词

[入口](./SKILL.md) · [工作流](./workflow.md) · [脚本](./script.md) · [音色](./tone.md) · [素材](./resources.md) · [音效](./sfx.md) · [质量门](./quality.md)

这是编排提示词。做主人的一支 Remotion 视频时，按本文从上到下执行。阶段顺序以 [workflow.md](./workflow.md) 为准；每一阶段的做法只以它点名的那份文件为准。不要把本文扩写成第二次创作，也不要在一份回复里凭感觉把配音、画面和成片一次做完。

本文不包含 Remotion 组件。画面和渲染打开官方 Skill（`npx skills add remotion-dev/skills`，见 [Remotion Skills](https://www.remotion.dev/docs/ai/skills)）。

## 你要交出来的东西

一支能从头播到尾的视频，加上视频工程里这些产物（目录名可随用户已有习惯，没有习惯时用 `production/`）：

- 确认过的简报
- 制作脚本（分镜）
- 素材清单（含许可）
- 主音轨
- 与主音轨对应的 SRT
- Remotion 工程、短样片、通过质量门后的成片

产物写在视频工程里，不写进 SkillsPocket，不提交密钥。

## 阶段 1 · 立项

读 [workflow.md](./workflow.md) 的用语、顺序和两条画面分支。然后向用户收齐立项项。用户已经给过的不要再问一遍。缺的只问缺的：片种、受众、平台、画幅、时长是硬性的还是「大约」、有没有出镜成片、是否商用、哪些事实必须由用户提供。

收齐后用几行复述简报，请用户确认。用户没有要求先搭工程时，确认前不搭工程，也不做阶段 2 以后的事。确认后进入阶段 0；用户若明确要求先搭工程，可以先做阶段 0，仍然不配音、不写正片。

用户若只要求「先写脚本」或「先不要渲染」，做到他点名的阶段就停，并写明下一步会是什么。

## 按阶段执行

每完成一阶段，在回复里留下状态，再进入下一阶段。状态用固定字段：简报、分镜、素材缺口、样音、主音轨路径、SRT 路径、短样片、音效是否听过、质量门里尚未通过的项。

### 阶段 0 · 环境

按 workflow.md「环境」。官方 Skill 和脚手架命令先给用户看。首次只渲染最小例子。不要在这一步配音。

### 阶段 2 · 脚本与分镜

打开 [script.md](./script.md)，按片种的段落骨架写制作脚本。产品介绍和技术讲解里，凡是演示产品或操作的段落，写明真实素材路径或「缺口」。

把脚本交给用户。在用户明确确认分镜之前：不调用 TTS，不克隆声音，不下载语音模型，不铺全片，不正式渲染。可以并行做阶段 0，以及只读的素材查找。

### 阶段 3 · 素材

打开 [resources.md](./resources.md)。能拿到的截图、录屏和官方素材先拿到。代码绘制的产品界面是最后手段，而且必须在清单里标明；会让人误以为是真界面时，画面或旁白里也要说清。

许可栏空着的条目不能进画面。

### 阶段 4 · 主音轨

打开 [tone.md](./tone.md)。

- 当前会话不在主人的 Mac 上：直接说明够不到 `127.0.0.1:3901`，不要去连，也不要把连不上说成 AudioSmith 坏了。按 tone.md 的降级询问用户。
- 在主人的 Mac 上且 AudioSmith 可用：先做样音（术语、中英混读、一个长句）。用户听过并同意音色之后，再合成全长。只把旁白正文送进去。
- 用户要自己录音：不调用 TTS，等他确认音轨。
- 用户给了出镜成片：不另做一条念同一篇稿的 TTS。主音轨是剪顺后的原声。

下载模型、删除音色或模型、克隆声音，各自再要一次明确同意。

### 阶段 5 · 字幕时间轴

仍按 tone.md「时间轴」。时间戳来自刚确认的主音轨。用制作脚本校对专名和漏字，不把没念出来的句子写进字幕。抽查开头、中段、结尾和长停顿。

### 阶段 6 · 画面

用官方 Remotion Skill 编写和预览。时长用主音轨的实测长度，加上约定的片头片尾，不用字数估算。素材按清单进对应段落；辅助录屏的解说默认静音，主音轨只留一份。

长片先做约 1～2 分钟短样片，内容要包含真实旁白、字幕、至少一处真实素材和一处转场。把短样片交给用户。他指出的字体、配色、节奏和动画密度，固定下来再扩展。短片的第一版整片同样要人看过。

渲染命令先说明输出路径，用户同意再执行。用户若已在本轮说过「样片可以直接渲染」，记录这句话并执行，不要为此再停一次。这句话不包括正式导出。

### 阶段 7 · 音效与配乐

打开 [sfx.md](./sfx.md)。先从个人库和 Video.md 里的本地、免配额来源列少量候选，请用户听。没有试听结论，不要宣称音效已经合适。旁白出现时压低配乐。音效打在有意义的动作上，不要每句都响。

### 阶段 8 与 9 · 质量门和导出

打开 [quality.md](./quality.md)，逐项做必过检查。有失败项就回到它写明的阶段，改完再测失败项以及被连带影响的项。全部必过、且用户同意导出之后，再渲染成片，并按 workflow.md 归档。

导出文件要完整播放一遍，核对画幅裁切、字幕、声音和片尾。上传由人做。

## 修改时

一次处理用户提出的一到两处。用大白话理解他的意见即可，例如精简某一段、改竖屏、换一种声音感觉、改配色、把某一段换成时间轴、加一个以后每期都用的片头。

动到旁白正文、音色、语速或停顿：重做受影响的主音轨、SRT，以及后面的画面和音效时间。动到素材：改清单和对应场景。只动音效音量或切点：保持主音轨和 SRT 不动。

## 不要做的事

- 不要在分镜确认前生成全长配音或正式渲染。
- 没有用户提供的出镜成片时，不要做成真人出现在镜头前。独立口播是配音、字幕和动态图形。
- 不要把屏幕文字和素材备注送进 TTS。
- 不要用代码画一张本可以截到或录到的产品界面，除非用户接受，并且清单已标明。
- 不要在远程或云端会话里声称已经调用主人 Mac 上的 AudioSmith。
- 不要把 Edge TTS 说成音色设计或声音克隆。
- 不要发明用户没讲过的个人经历、口碑或产品数据。
- 不要因为找到了音效文件就当作已经试听。
- 不要把 API key、令牌写进仓库、脚本或提交。
