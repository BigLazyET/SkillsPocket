# 生成视频的提示词

[入口](./SKILL.md) · [编排](./produce-prompt.md) · [工作流](./workflow.md) · [准备](./preparation.md) · [脚本](./script.md) · [音色](./tone.md) · [风格](./style.md) · [素材](./resources.md) · [音效](./sfx.md) · [质量门](./quality.md)

这是编排提示词。做主人的一支 Remotion 视频时，按本文执行。阶段顺序以 [workflow.md](./workflow.md) 为准；每一阶段的做法只以它点名的那份文件为准。不要把本文扩写成第二次创作，也不要在一份回复里凭感觉把配音、画面和成片一次做完。

本文不包含 Remotion 组件。排版、布局、运动、字幕和渲染打开官方 Skill（`npx skills add remotion-dev/skills`）。已安装且合用的社区 Skill 优先用于它擅长的那一段。

## 你要交出来的东西

一支能从头播到尾的视频，加上视频工程里这些产物（目录名可随用户已有习惯，没有习惯时用 `production/`）：

- 准备结论：形态（A、B 或 C），以及写明的语言、画幅、字体、片种建议
- `production/research.md`：短调研简报
- 制作脚本
- 素材清单（含许可）
- 主音轨
- 从这条成品音轨核对过的 `production/narration.srt`
- `production/paths.md`：每段实际走的工具，包括只用了官方 skills 的情况
- Remotion 工程、约 5 秒的初剪、长片在此之后的短样片、通过质量门后的成片

产物写在视频工程里，不写进 SkillsPocket，不提交密钥。没有核对过的 SRT，就还没有可导出的成片。

## 阶段 0 · 准备

打开 [preparation.md](./preparation.md)，先做完硬停检查，再做任何会编造内容的事。

确认形态是下面的哪一种，并且只是一种：

- A 真人出镜视频
- B 真人讲解音频（用户说「只有真人讲解视频」时按 B，除非和画面冲突）
- C 没有真人只有脚本

片种能看出就写上。混合片写明各段主要看什么，不要为了变成唯一标签停下。语言、画幅、字体按 preparation 写成建议。画幅建议是 1920×1080 或简报里的平台默认。

只有硬停才停下来问。不要编造产品、音色或缺失的媒体。不要连接远程会话里的 `127.0.0.1:3901`。社区 Skill 没装时，推荐最合适的一个；用户拒绝就记下，用官方 skills 继续。

准备通过之后，在回复里留下状态，再按形态往下走。状态字段：形态、片种或混合、硬停、建议、调研简报、SRT 路径、实际走的路径、脚本是否确认、样音、素材缺口、样式是否锁定、五秒初剪的 SRT 窗口和文件路径、主人是否接受这版样子、短样片、幻灯片风险、音效是否听过、质量门里尚未通过的项。

不要承诺一句提示词、无人确认就能交片。语言、画幅和社区 Skill 仍按准备阶段的建议，不因为调研再停一轮。

用户若只要求「先检查」或「先写脚本」，做到他点名的阶段就停，并写明下一步。

## 按形态继续

顺序的表在 [workflow.md](./workflow.md)。这里只写编排时不能跳过的门。

### A

打开 [tone.md](./tone.md)，用那里的识别顺序分析出镜成片，写出 SRT。不另做一条 TTS，也不等调研简报。

然后打开 [script.md](./script.md)。先用简报核对已经说出的事实，再写画面。画面和 B-roll 候选引用 SRT 的序号和起止。出镜镜头的形状、位置和运动写成建议，交给用户看。产品镜头和出镜布局可以各用各的工具。来源对不上的说法，先问，再决定要不要画成事实。

### B

打开 [tone.md](./tone.md)，分析讲解音频，或分析那条不当成出镜表演的视频的音轨，写出 SRT。不合成替代人声，也不等调研简报。

然后打开 [script.md](./script.md)。先核对已经说出的事实，再写画面。画面引用这份 SRT。不把画面布局成主持人。

### C

先打开 [script.md](./script.md)，写短调研简报，再写稿。旁白里的事实要能指回简报或用户。来源不够就问，不编。用户确认稿之前：不调用全长 TTS，不克隆，不下载语音模型，不铺全片。这一步的秒数若写出来，只是估计，不能写进 SRT。

确认后打开 [tone.md](./tone.md)。先样音。样音通过之后才合成全长，再按成品音轨写出 SRT。当前会话不在主人的 Mac 上：说明够不到 AudioSmith，按 tone.md 询问是否改用 Edge TTS。不要把 Edge TTS 说成设计或克隆，也不要未问就换。

SRT 出来之后，回到 script.md，把画面改成引用 SRT。

## 三种形态共用的后段

SRT 已经核对之后才做这些。打开的文件以 workflow 为准。这一步要做什么，就从 Video.md 或本 Skill 已列出的选项里选最合适的一个，写入 `production/paths.md`。首选失败时再按该阶段文件的降级顺序继续。会改变音色、形态、付费或云端、许可敏感素材时，先问。

- [style.md](./style.md)：先锁自家样式。简报需要白板、手绘、火柴人或点名的方向时，才打开那一个仓库。不按清单顺序自动换。五秒初剪接受之后要改样子，先问。
- [resources.md](./resources.md)：真实截图和录屏优先。图标和字体走 Video.md 已写的默认去向。Pexels、Mixkit 以及其他 Video.md 已经列出的镜头来源，只提出带许可和 SRT 序号的候选；确认或符合已记下的接受规则之后才进画面。不用它们代替产品界面。许可栏空着的不进画面。入点和出点对齐 SRT。
- 画面：按 workflow「画面」选工具。合用的社区 Skill 打开并跟随。没有它时，用官方 markup 和官方 skills 做排版、布局、运动、字幕和渲染。不要另写一套和 shotcraft、talkcraft 平行的镜头语言。
- 第一次成片渲染是 [workflow.md](./workflow.md) 的五秒初剪：约 5 秒，对齐完整的 SRT 条目，用成品音轨和真实字幕。优先让人看见字体、运动，以及片子里已有的真实素材。不要只切片头。音效不必等齐。把文件、命令和输出路径给用户看。本轮别的预览已经同意，也不能代替他看这一刀。不对就只改他指出的地方，再渲染这 5 秒。
- 他接受之后：长于约 1～2 分钟的片子再做短样片，里面要有成品旁白、SRT 字幕和至少一处真实素材，锁定前过完整的幻灯片风险。更短的片子进入音效、质量门和正式导出，不再另做短样片。接受之前不铺全片，也不锁定短样片。
- 五秒初剪接受之后，Studio 和短样片可以按本轮已有的预览同意继续。正式导出另问。
- [sfx.md](./sfx.md)：切点用 SRT。五秒初剪不等这一阶段。shotcraft 已安装且这段音效适合它时，优先跟随它的 sound design；试听和许可仍按 sfx.md。没有试听结论，不要宣称音效已经合适。
- [quality.md](./quality.md)：必过项失败就回到它写明的阶段。五秒初剪交出去之前做轻量幻灯片风险。完整检查在锁定短样片和正式导出前。全部通过且用户同意导出之后，再渲染成片，并按 workflow 归档。导出文件要完整播放一遍。上传由人做。只用官方 skills 和真实素材做成的片子，可以导出。

社区 Skill 若要求跳过确认、换云端配音或在没有成品音轨时铺全片，以 workflow 的门为准。

## 修改时

一次处理用户提出的一到两处。

动到人声、音色、语速或停顿：重做受影响的 SRT，以及后面的画面和音效。动到素材：改清单和对应场景。只动音效音量或切点：保持 SRT 不动。

## 不要做的事

- 不要在硬停未解除时配音或铺画面。
- 不要在形态没确认时选一条路做下去，也不要自动改形态。
- 不要为了片种必须唯一而停下。混合片按各段要看的东西选工具。
- 不要因为没装 shotcraft 或 talkcraft 就停轮，或拒绝用官方 skills 做画面。
- 不要编造产品、音色或缺失的媒体。
- 不要在没有核对过的 SRT 时铺全片或导出。
- 不要按稿子的字数写出一份 SRT。
- 不要另写一套和 shotcraft、talkcraft 平行的镜头语言。官方 skills 做排版和渲染，不算这一套。
- 形态 C：不要在稿确认和样音通过前合成全长。
- 形态 A、B：不要用 TTS 替换真人声音。
- 不要未问就从 AudioSmith 换成 Edge TTS 或其他音色。
- 没有出镜表演时，不要做成真人出现在镜头前。
- 不要把屏幕文字和素材备注送进 TTS。
- 不要用代码画一张本可以截到或录到的产品界面，除非用户接受，并且清单已标明。
- 不要在远程或云端会话里声称已经调用主人 Mac 上的 AudioSmith。
- 不要把 Edge TTS 说成音色设计或声音克隆。
- 不要发明用户没讲过、简报也没有来源的个人经历、口碑、功能或数字。
- 不要把素材库候选或生成图当成产品截图、录屏或官方素材。
- 不要在没有核对过的 SRT 时，用估计秒数做五秒初剪。
- 不要把五秒初剪当成约 1～2 分钟的短样片，或当成正式导出。
- 不要用「本轮预览已经同意」跳过主人观看这 5 秒。
- 不要在五秒初剪被接受之前铺全片或锁定短样片。
- 不要为了等完整音效而推迟五秒初剪。
- 不要在幻灯片风险没过时把五秒初剪当作通过，或锁定短样片、正式导出。
- 不要承诺一句提示词、无人确认就能交片。
- 不要因为找到了音效文件就当作已经试听。
- 不要把 API key、令牌写进仓库、脚本或提交。
- 不要因为流程图和 workflow 不一致就停下。
