# 工作流

[入口](./SKILL.md) · [编排](./produce-prompt.md) · [工作流](./workflow.md) · [准备](./preparation.md) · [脚本](./script.md) · [音色](./tone.md) · [风格](./style.md) · [素材](./resources.md) · [音效](./sfx.md) · [质量门](./quality.md)

本文件只规定顺序、交接物和停止条件。某一阶段怎么做，打开该阶段点名的文件。这里不重复那些规约，也不写 Remotion 组件。

核对日期：2026-11-10。工具、素材和许可以 [Video.md](../Video.md) 已写明的事实为准。发布背景见 Video.md 的个人发布工作流。流程图见 [Remotion-AI-Video-Workflow.mmd](../Remotion-AI-Video-Workflow.mmd)。图和本文件不一致时，以本文件为准，不要为此停下。

## 用语

| 用语 | 含义 |
|---|---|
| 片种 | 产品介绍、口播讲解、技术讲解。用来组织叙事。画面工具按这部片子实际要给人看的东西来选 |
| 形态 | A 真人出镜视频、B 真人讲解音频、C 没有真人只有脚本。三选一 |
| 制作脚本 | 要说的话或听写、只上屏的文字、素材和动作备注。画面引用 SRT 的序号和起止 |
| SRT | 配音与画面的依据。逐字稿定义说什么，成品音轨定义何时说，SRT 记录序号、起止和文本。文件是 `production/narration.srt` |
| 主音轨 | 成品的那一条人声。A、B 是真人声音。C 是确认后的 TTS。只留一份 |
| 五秒初剪 | 第一次成片画面。约 5 秒，对齐完整的 SRT 条目。用来看样式、字体、运动，以及是否对上简报。是预览，不是正式导出 |
| 短样片 | 长于约 1～2 分钟的片子，在五秒初剪被接受之后再做的约 1～2 分钟。不代替五秒初剪。不长于这个长度的片子不再另做短样片 |
| 代码绘制界面 | 用代码画出的产品界面，不是截图或录屏。素材清单里必须标明 |
| 质量门 | 进入全片或正式导出前必须通过的检查 |

视频工程里的稿、清单、音轨和 SRT 放在该工程的 `production/`，不要写进 SkillsPocket。

## 顺序

每次都从准备开始。硬停没解除时，后面的表不执行。建议项写明即可，不挡住后面的阶段。用户本轮如果只要求做到某一阶段，做到那里就停。

| 阶段 | 打开 | 进入条件 | 交出 | 停下 |
|---|---|---|---|---|
| 0 准备 | [preparation.md](./preparation.md) | 用户提出做片 | 确认过的形态，以及写明的建议 | 只有硬停。见下一节 |
| 1 分支 | 下表 | 准备已通过硬停 | 短调研简报、成品主音轨、核对过的 `production/narration.srt`、引用该 SRT 的制作脚本 | 形态 C 在确认稿和样音通过前不做全长 TTS。没有成品音轨就没有可依据的 SRT。没有核对过的 SRT，不铺全片、不导出。要写成事实但来源对不上时，停下问 |
| 2 风格 | [style.md](./style.md) | 叙事已经写进脚本 | 自家样式，或简报确实需要的那一个风格仓库 | 五秒初剪接受之后要改样子，先问 |
| 3 素材 | [resources.md](./resources.md) | SRT 已核对；演示缺口已列出 | 素材清单 | 许可不明或和商用冲突的不进画面 |
| 4 画面 | 本文件「画面」和「五秒初剪」。素材交接见 [resources.md](./resources.md) | 选定窗口的样式、字体、运动和素材已齐；成品旁白和核对过的 SRT 已在 | 先是五秒初剪。接受之后，长片再做短样片 | 初剪未接受：不铺全片，不锁定短样片。长片在短样片通过前不铺开。锁定短样片前做完整的幻灯片风险 |
| 5 音效与配乐 | [sfx.md](./sfx.md) | 五秒初剪已接受。长片还要短样片方向已定。切点用 SRT | 分轨音效和配乐，以及人听过的结论 | 只找到文件、没有试听，不算完成。完整音效不挡住五秒初剪 |
| 6 质量门 | [quality.md](./quality.md) | 有一版含主音轨、SRT、字幕和音效的预览 | 必过项的通过记录 | 有必过项失败就不正式导出 |
| 7 导出与归档 | [quality.md](./quality.md) 的导出检查 | 质量门已通过，用户同意导出 | 成片和可再编辑的工程 | 上传和发布由人确认 |

SRT 和脚本的先后只由形态决定。风格、素材、画面、音效、质量门、导出都引用这份 SRT，不另估一套秒数。

| 步骤 | A 真人出镜视频 | B 真人讲解音频 | C 没有真人只有脚本 |
|---|---|---|---|
| 准备之后 | [tone.md](./tone.md)：从与画面一致的人声写出 SRT。简报不挡这一步 | [tone.md](./tone.md)：从讲解音频写出 SRT。简报不挡这一步 | [script.md](./script.md)：先写短调研简报，再写稿。确认前不做全长 TTS |
| 然后 | [script.md](./script.md)：简报核对已经说出的事实；画面和 B-roll 候选标上 SRT 序号，并记下出镜布局 | [script.md](./script.md)：同样先核对事实，再按 SRT 写画面。不布局出镜表演 | [tone.md](./tone.md)：样音通过后合成全长，再写出 SRT |
| 然后 | 进入阶段 2 | 进入阶段 2 | 回到 [script.md](./script.md)，把画面引用改成 SRT 的序号和起止，然后进入阶段 2 |

改了人声、语速或停顿之后，回到 [tone.md](./tone.md) 重做受影响的 SRT，再改画面和音效。不要只把画面拉长。

## 不够就停

立刻停下，只在继续做会编出实质内容或越界的时候：

- 形态 A、B、C 两可，或互相冲突
- A 或 B 没有源文件路径
- C 既没有脚本或要点，也没有允许起草
- 要用的素材许可不清，或和商用冲突
- 这一步会改变音色、形态、付费或云端工具、许可敏感的素材

不要编造产品、经历、口碑、数字或没给过的媒体。旁白或画面要写成事实，但用户给的来源和当时能引用的公开页面都对不上时，停下问。缺的截图记成缺口，留到那一段再问，不为此停掉整轮，也不画成假界面。

语言、画幅、字体、片种能从简报看出，或可以给出建议时，写进准备结论并继续。画幅建议用 1920×1080，或简报里的平台默认。这是写明的建议，不是静默套用。用户否定再改。社区 Skill 没装，见「画面」，不构成硬停。

形态 C 的全长合成另有两道门，都在 [tone.md](./tone.md)：稿已确认，样音已通过。

没有从成品音轨核对过的 SRT：不铺全片，不正式导出。只有稿子时写出的秒数只是估计，不能写进 SRT。

## 命令要不要再问

安装、下载模型、克隆、删除、新建工程的脚手架，以及正式导出：把命令和输出路径给用户看，同意后再执行。

预览、Studio 和短样片：本轮已经同意过预览，或用户说过样片可以直接渲染，后面的同类预览继续做。还没有任何一次同意时，第一次预览把命令给用户看。这次同意不包括正式导出，也不代替主人观看五秒初剪。

## 五秒初剪

样式、字体、运动做法，以及这一窗要用的素材都已定，并且成品旁白和核对过的 `production/narration.srt` 都在，第一次成片渲染就是约 5 秒的初剪。后面段落还缺的素材不挡住这一窗。这不是约 1～2 分钟的短样片，也不是全片。没有核对过的 SRT 时，不用稿子上的估计秒数切出这一段。

选窗：大约 5 秒，起止落在完整的 SRT 条目上。为了不切开字幕，略短或略长都可以。优先能同时看见字体和运动的一段。片子里有真实素材时，这一窗里要有一条，不要只切片头标题。这一窗用成品音轨和真实字幕。

音效和配乐不是这一刀的前提。已经有的简单声音可以带上。要看的是样式、字体、动画，以及画面是否对上简报。

这是预览，不是正式导出。把文件、命令和输出路径给用户看。本轮已经同意过别的预览，也不能代替他看这一刀。他指出哪里不对，只改那些地方，再渲染这约 5 秒。他接受之后，长片才做 1～2 分钟短样片；不长于约 1～2 分钟的片子才进入音效、质量门和正式导出。接受之前不铺全片，也不锁定短样片。正式导出仍另问。接受之后的 Studio 和短样片渲染，按上一节的预览同意继续。

整片只比这个窗口长几秒时，初剪可以覆盖其中大部分。样子接受之前仍不正式导出。

这一刀做 [quality.md](./quality.md) 的轻量幻灯片风险。片子承诺了动作、演示或讲解时，只有标题卡的 5 秒不算通过。锁定短样片前和正式导出前的完整检查仍要做。

准备阶段那个几秒字幕、没有旁白的最小例子只检查工具链，不是这刀初剪。

## 路径失败时

先看这一步要完成的事，再从 Video.md 或本 Skill 已经列出的选项里挑最合适的一个。调研、空镜、图解、字幕、音效、配音和渲染都这样。选中的写进 `production/paths.md`。不另做评分表，也不引入清单外的供应商。付费或云端仍先问。

然后才是降级：首选缺失、报错、被挡住，或明显不适合这台机器和这种形态时，按该阶段文件的顺序试下一条。失败原因和实际使用的路径也写入 `production/paths.md`。工程还没有时先写在回复里，工程出现后补上。

下一条必须来自 Video.md 已经列出的技能或工具，或本 Skill 已经写过的门。不要临时找清单以外的产品。

先问用户、不要自动换，如果：

- 可自动尝试的路径都失败了
- 换过去会改变观众听到的音色
- 会把形态 A、B、C 换成另一种
- 会用到付费或云端服务
- 会用许可不清楚、或和本片商用要求冲突的素材

各阶段的首选：

| 阶段 | 首选 | 顺序写在 |
|---|---|---|
| 形态 C 的配音 | 主人的 Mac 上能叫到的 AudioSmith | [tone.md](./tone.md) |
| 从成品音轨写 SRT | AudioSmith 的转写，否则 whisper.cpp | [tone.md](./tone.md) |
| 字幕、排版、布局、运动、预览、渲染 | 官方 remotion-dev/skills | 本文件「画面」 |
| 产品界面和宣传节奏 | 已安装且合用的 video-shotcraft；否则官方 skills 加真实画面 | 本文件「画面」 |
| 口播驱动的讲解和出镜布局 | 已安装且合用的 video-talkcraft；否则官方 skills | 本文件「画面」 |
| 风格 | 自家样式。简报需要某种画风时才打开对应仓库 | [style.md](./style.md) |
| 图标、字体、录屏 | Video.md 第 6 节和第 7 节的默认去向 | [resources.md](./resources.md) |
| 空镜和封面 | Video.md 第 7 节已列出的镜头站，只作候选 | [resources.md](./resources.md) |
| 音效 | 个人库，然后 `@remotion/sfx` 与 earshot | [sfx.md](./sfx.md) |

## 画面

按这部片子主要给人看的东西选工具。片种只帮助判断叙事，不单独决定打开哪一个仓库。技术讲解可以是录屏、结构图、白板或靠字体讲清楚，不必打开 video-talkcraft。

社区 Skill 是优先工具，不是开工依赖。已安装、并且合用时，打开并跟随它做那一部分。没装、用户拒绝安装、不合用，或只覆盖片子的一部分时，其余用官方 [remotion-dev/skills](https://www.remotion.dev/docs/ai/skills) 做排版、布局、运动、字幕和渲染，素材用清单里已有的真实画面。官方 skills 与社区 Skill 对 Remotion 的写法不一致时，以官方 Skill 为准。

| 主要在看什么 | 优先 |
|---|---|
| 产品界面、宣传节奏 | [video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft) |
| 口播驱动的讲解、出镜镜头怎么摆 | [video-talkcraft](https://github.com/Vincentwei1021/video-talkcraft) |
| 操作录屏 | 清单里的录屏，用官方 skills 放进 SRT 的起止 |
| 系统结构 | Video.md 的 Anatomy。它产出的是图，不是成片 |
| 白板、手绘、火柴人 | [style.md](./style.md) 里对上的那一个仓库；接进工程仍用官方 skills |
| 靠字体和层级讲清楚 | 官方 skills。不必再打开社区镜头库 |

混合片是常态，例如产品介绍加上真人出镜。产品镜头和出镜布局可以各用各的合适工具。两套完整的导演流程会改写同一批镜头时，先问用哪一套主导。不要因为同时像两种片种就停掉整轮。

不要另写一套和 shotcraft、talkcraft 平行的镜头语言。合用的社区 Skill 已经规定了镜头卡或 SHOTBOOK 时，跟随它。没有那份 Skill 时，用官方 markup 和官方 skills 把字幕、版式和运动做出来。

词级时间可以有，但必须落在 `production/narration.srt` 对应条目的起止之内。仓库不复制进 SkillsPocket。安装命令见 [preparation.md](./preparation.md)，同意后再执行。用户拒绝安装就走官方 skills，并把这条写入 `production/paths.md`。

空镜和封面只按 [resources.md](./resources.md) 提出候选，确认或符合已记下的接受规则之后才进画面。素材库和生成图不代替产品截图、录屏或官方素材。五秒初剪先做轻量幻灯片风险。锁定短样片之前再做完整的那一节。

其中一步失败时：先用该 Skill 自己的下一步。整个 Skill 跑不起来，或用户已经选定的镜头卡因此用不上，记下失败；后者先问。官方渲染也失败时，停下来问，不换一个清单外的渲染器。

## 社区 Skill 与这些门冲突时

以本文件为准。准备先做。硬停才问住整轮。形态先确认。SRT 只来自成品音轨。主人的 Mac 上叫得到 AudioSmith 时，形态 C 用它；Edge TTS 只在用户同意后作为降级。正式导出前要有质量门和用户同意。

因此不跟随这些做法：video-shotcraft 的自主自由创作若中途不再确认，不能用来跳过上面的门。video-talkcraft 的默认画幅、Fish Audio、未先给用户看就剪口播，以及自动升级 Remotion，也不覆盖这些门。Fish Audio 不在 Video.md 的语音清单里，不把它加进降级。形态 A 的出镜形状、位置和运动以脚本里写明并交给用户看过的决定为准。

## 和 Video.md 的用词

Video.md 第 8 节表格用「主时间轴」指确认后的录音或剪顺后的口播原声，并写明 SRT 依据那条音轨生成。本文件不另做一份叫时间轴的文件。成品音轨决定何时说，SRT 记下序号、起止和文本。若两处被读成两套时间，按本文件的 SRT 做，并在回复里指出用词差异。不要为此停下。

Video.md 把无出镜分成「录音或 TTS」一条。本文件把无出镜再分成 B 和 C。声画仍遵守 Video.md：主音轨只留一份；辅助录屏的解说默认静音；B-roll 盖住画面时，A 的人声连续。

Video.md 把 video-shotcraft、video-talkcraft 写成可评估的候选，并写明没有足够比较证据称为最优。本文件在已安装且合用时优先打开它们。这不把它们写成依赖，也不改写清单上的排名。

## 归档时留下什么

- 可编辑的 Remotion 工程。
- 制作脚本、`production/research.md`、素材清单、主音轨、`production/narration.srt`、来源说明 `production/narration-srt.md`、`production/paths.md`。
- 需要署名的第三方素材的署名文本。
- 五秒初剪接受的背景、字体、动画密度，以及它用的 SRT 窗口。
- 听过、以后还要用的音效，按 [sfx.md](./sfx.md) 记进个人库索引。

封面、标题、简介和实际上传由人做。

## 与两份外部材料的差异

| 来源 | 核对到的内容 | 本流程怎么取 |
|---|---|---|
| [Smartpigai 的文章](https://x.com/Smartpigai/article/2073753428212478384)（2026-07-05） | 先确认分镜，再配音，再渲染；装依赖和跑命令先问；第一次先做最小例子；1920×1080；时长跟随配音；底部字幕；深色背景；用口语描述声音；搭建时写的是 Edge TTS | 形态 C 仍先确认稿，再样音，再全长合成，再渲染。安装和正式导出先问。最小例子、时长跟随成品声音、底部字幕采纳。画幅未说明时建议 1920×1080 并写明，不静默套用，也不为此停掉整轮。配音在 AudioSmith 可用时不走 Edge TTS。A、B 的 SRT 来自真人声音 |
| [Launch Video on X](https://www.remotion.dev/prompts/launch-video-on-x)（页面核对于 2026-11-10） | 一条提示词写完约 37 秒、8 个场景。界面要求用代码画出来。没有要求先访问真实产品。画幅写成 1080×700 | 采纳「每个场景写清观众看到什么」。不采用该画幅。有真实截图、录屏或官方素材时不用代码画界面。不在 SRT 核对前铺全片 |
