# 工作流

[入口](./SKILL.md) · [编排](./produce-prompt.md) · [工作流](./workflow.md) · [准备](./preparation.md) · [脚本](./script.md) · [音色](./tone.md) · [风格](./style.md) · [素材](./resources.md) · [音效](./sfx.md) · [质量门](./quality.md)

本文件只规定顺序、交接物和停止条件。某一阶段怎么做，打开该阶段点名的文件。这里不重复那些规约，也不写 Remotion 组件。

核对日期：2026-11-10。工具、素材和许可以 [Video.md](../Video.md) 已写明的事实为准。发布背景见 Video.md 的个人发布工作流。流程图见 [Remotion-AI-Video-Workflow.mmd](../Remotion-AI-Video-Workflow.mmd)。

## 用语

| 用语 | 含义 |
|---|---|
| 片种 | 产品介绍、独立口播、技术讲解。Video.md 称产品宣传、口播讲解。片种决定画面阶段打开哪一个社区 Skill，不决定形态 |
| 形态 | A 真人出镜视频、B 真人讲解音频、C 没有真人只有脚本。三选一，在准备阶段确认 |
| 制作脚本 | 要说的话或听写、只上屏的文字、素材和动作备注。画面引用 SRT 的序号和起止 |
| SRT | 配音与画面的依据。逐字稿定义说什么，成品音轨定义何时说，SRT 记录序号、起止和文本。文件是 `production/narration.srt` |
| 主音轨 | 成品的那一条人声。A、B 是真人声音。C 是确认后的 TTS。只留一份 |
| 短样片 | 长片先做的约 1～2 分钟。片子本身不长于这个长度时，第一版整片就是样片，仍要人看过再导出 |
| 代码绘制界面 | 用代码画出的产品界面，不是截图或录屏。素材清单里必须标明 |
| 质量门 | 进入全片或正式导出前必须通过的检查 |

视频工程里的稿、清单、音轨和 SRT 放在该工程的 `production/`，不要写进 SkillsPocket。

## 顺序

每次都从准备开始。准备没通过时，后面的表不执行。用户本轮如果只要求做到某一阶段，做到那里就停。

| 阶段 | 打开 | 进入条件 | 交出 | 停下 |
|---|---|---|---|---|
| 0 准备 | [preparation.md](./preparation.md) | 用户提出做片 | 确认过的形态和片种，以及该形态所需项都就绪 | 缺条件。见下一节 |
| 1 分支 | 下表 | 准备已通过 | 成品主音轨、核对过的 `production/narration.srt`、引用该 SRT 的制作脚本 | 形态 C 在确认稿和样音通过前不做全长 TTS。没有成品音轨就没有可依据的 SRT。没有核对过的 SRT，不铺全片、不导出 |
| 2 风格 | [style.md](./style.md) | 叙事已经写进脚本 | 风格简报，以及准备打开的一个资源 | 不一次安装全部风格仓库。锁定要等短样片 |
| 3 素材 | [resources.md](./resources.md) | SRT 已核对；演示缺口已列出 | 素材清单 | 许可不明的不进画面 |
| 4 画面 | 本文件「画面」。素材交接见 [resources.md](./resources.md) | SRT、脚本、风格简报、清单齐全 | 短样片；通过后再扩展 | 长片在短样片通过前不铺开。A 的出镜布局没决定也不铺全片 |
| 5 音效与配乐 | [sfx.md](./sfx.md) | 短样片方向已定；切点用 SRT | 分轨音效和配乐，以及人听过的结论 | 只找到文件、没有试听，不算完成 |
| 6 质量门 | [quality.md](./quality.md) | 有一版含主音轨、SRT、字幕和音效的预览 | 必过项的通过记录 | 有必过项失败就不导出 |
| 7 导出与归档 | [quality.md](./quality.md) 的导出检查 | 质量门已通过，用户同意导出 | 成片和可再编辑的工程 | 上传和发布由人确认 |

SRT 和脚本的先后只由形态决定。风格、素材、画面、音效、质量门、导出都引用这份 SRT，不另估一套秒数。

| 步骤 | A 真人出镜视频 | B 真人讲解音频 | C 没有真人只有脚本 |
|---|---|---|---|
| 准备之后 | [tone.md](./tone.md)：从与画面一致的人声写出 SRT | [tone.md](./tone.md)：从讲解音频写出 SRT | [script.md](./script.md)：写稿。确认前不做全长 TTS |
| 然后 | [script.md](./script.md)：按 SRT 写画面，并记下出镜布局 | [script.md](./script.md)：按 SRT 写画面。不布局出镜表演 | [tone.md](./tone.md)：样音通过后合成全长，再写出 SRT |
| 然后 | 进入阶段 2 | 进入阶段 2 | 回到 [script.md](./script.md)，把画面引用改成 SRT 的序号和起止，然后进入阶段 2 |

改了人声、语速或停顿之后，回到 [tone.md](./tone.md) 重做受影响的 SRT，再改画面和音效。不要只把画面拉长。

## 不够就停

准备阶段或其后任一阶段，只要安全往下做的条件不够，立刻停下来问用户。不要编造产品、音色、画幅、镜头清单或缺失的媒体。

至少包括：形态、片种、画幅、语言、该形态的源文件路径、形态 C 的脚本或要点、形态 C 的音色、片种所需的社区 Skill、进画面所缺的已许可素材。核对方法在 [preparation.md](./preparation.md)。

形态 C 的全长合成另有两道门，都在 [tone.md](./tone.md)：稿已确认，样音已通过。

没有从成品音轨核对过的 SRT：不铺全片，不正式导出。只有稿子时写出的秒数只是估计，不能写进 SRT。

## 路径失败时

每一步先走该阶段文件里的首选。首选缺失、报错、被挡住，或明显不适合这台机器和这种形态时，按该文件的顺序试下一条。把试过的路径、失败原因和实际使用的路径写入 `production/paths.md`。工程还没有时先写在回复里，工程出现后补上。

下一条必须来自 Video.md 已经列出的技能或工具，或本 Skill 已经写过的门。不要临时找清单以外的产品。

先问用户、不要自动换，如果：

- 可自动尝试的路径都失败了
- 换过去会改变观众听到的音色
- 会把形态 A、B、C 换成另一种
- 会用到付费或云端服务
- 会用许可不清楚、或和本片商用要求冲突的素材

安装、下载、克隆、删除和渲染仍先把命令给用户看，同意后再执行。

各阶段的首选：

| 阶段 | 首选 | 顺序写在 |
|---|---|---|
| 形态 C 的配音 | 主人的 Mac 上能叫到的 AudioSmith | [tone.md](./tone.md) |
| 从成品音轨写 SRT | AudioSmith 的 `transcribe`，否则 whisper.cpp | [tone.md](./tone.md) |
| 字幕绘制、工程、预览、渲染 | 官方 remotion-dev/skills | 本文件「画面」 |
| 产品介绍的镜头 | 已安装的 video-shotcraft | 本文件「画面」 |
| 口播讲解和技术讲解的镜头 | 已安装的 video-talkcraft | 本文件「画面」 |
| 风格 | 用户点名的一个；没有点名就用短样片 | [style.md](./style.md) |
| 图标、字体、录屏 | Video.md 第 6 节和第 7 节的默认去向 | [resources.md](./resources.md) |
| 音效 | 个人库，然后 `@remotion/sfx` 与 earshot | [sfx.md](./sfx.md) |

## 画面

片种决定打开哪一个已安装的社区 Skill，并跟随它的镜头做法。官方 [remotion-dev/skills](https://www.remotion.dev/docs/ai/skills) 负责创建、markup、Studio、渲染和字幕。两边对 Remotion 的写法不一致时，以官方 Skill 为准。

| 片种 | 打开 | 跟随它做的事 |
|---|---|---|
| 产品介绍 | [video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft) | 真实页面、镜头配方卡、Remotion 动画、节拍和音效设计 |
| 口播讲解、技术讲解 | [video-talkcraft](https://github.com/Vincentwei1021/video-talkcraft) | 成品配音、SRT 或词级时间、SHOTBOOK、动效配方卡、证据截图；形态 A 的出镜布局也在这里实现 |

安装命令在 [preparation.md](./preparation.md)。仓库不复制进 SkillsPocket。

同一支片子被同时说成产品介绍和口播讲解时，停下来问打开哪一个，不要两个导演流程一起跑。

词级时间可以有，但必须落在 `production/narration.srt` 对应条目的起止之内。画面、字幕和音效引用这份 SRT。

降级：

1. 用上表那一个社区 Skill。其中一张卡或一个步骤失败时，仍按该 Skill 自己的下一张卡或恢复步骤做，不另写一套镜头语法。
2. 整个 Skill 报错、打不开或不适合本机：记下失败。接着只用官方 Remotion skills 完成创建、预览、渲染和字幕，素材用清单里已有的真实画面。不新写镜头配方。用户已经选定的镜头卡若因此用不上，停下来问。
3. [motiontemplates](https://github.com/motiontemplates/all) 只复用 Video.md 模板一节允许的布局或组件。不把整包当成第二个全片流程。
4. 两个社区 Skill 都不可用，或官方渲染也失败：停下来问。

## 社区 Skill 与这些门冲突时

以本文件为准。一次说清：

准备先做。条件不够就问。形态先确认。SRT 只来自成品音轨，估计秒数不能用来铺全片。主人的 Mac 上叫得到 AudioSmith 时，形态 C 用它；Edge TTS 只在用户同意后作为降级。正式导出前要有质量门和用户同意。

因此不跟随这些做法：video-shotcraft 的自主自由创作若中途不再确认，不能用来跳过上面的门。video-talkcraft 的默认画幅、Fish Audio、未先给用户看就剪口播，以及自动升级 Remotion，也不覆盖这些门。Fish Audio 不在 Video.md 的语音清单里，不把它加进降级。形态 A 的出镜形状、位置和运动以用户在 [script.md](./script.md) 里的决定为准。

## 和 Video.md 的用词

Video.md 第 8 节表格用「主时间轴」指确认后的录音或剪顺后的口播原声，并写明 SRT 依据那条音轨生成。本文件不另做一份叫时间轴的文件。成品音轨决定何时说，SRT 记下序号、起止和文本。若两处被读成两套时间，停下来指出差异，不要各走各的。

Video.md 把无出镜分成「录音或 TTS」一条。本文件把无出镜再分成 B 和 C，因为一个分析现成声音，一个在确认后合成。声画仍遵守 Video.md：主音轨只留一份；辅助录屏的解说默认静音；B-roll 盖住画面时，A 的人声连续。

Video.md 把 video-shotcraft、video-talkcraft 写成可评估的候选，并写明没有足够比较证据称为最优。本文件在主人的这一次制作里按片种指定打开哪一个。这不改写清单上的排名。

[Remotion-AI-Video-Workflow.mmd](../Remotion-AI-Video-Workflow.mmd) 仍是两条分支的图。执行以本文件的三种形态为准。图和本文件对不上时，停下来指出差异。

## 归档时留下什么

- 可编辑的 Remotion 工程。
- 制作脚本、素材清单、主音轨、`production/narration.srt`、来源说明 `production/narration-srt.md`、`production/paths.md`。
- 需要署名的第三方素材的署名文本。
- 短样片锁定的背景、字体、动画密度。
- 听过、以后还要用的音效，按 [sfx.md](./sfx.md) 记进个人库索引。

封面、标题、简介和实际上传由人做。

## 与两份外部材料的差异

| 来源 | 核对到的内容 | 本流程怎么取 |
|---|---|---|
| [Smartpigai 的文章](https://x.com/Smartpigai/article/2073753428212478384)（2026-07-05） | 先确认分镜，再配音，再渲染；装依赖和跑命令先问；第一次先做最小例子；1920×1080；时长跟随配音；底部字幕；深色背景；用口语描述声音；搭建时写的是 Edge TTS | 形态 C 仍先确认稿，再样音，再全长合成，再渲染。先问命令、最小例子、时长跟随成品声音、底部字幕采纳。画幅未说明时停下来问，1920×1080 只是询问时的常见例子。配音在 AudioSmith 可用时不走 Edge TTS。A、B 的 SRT 来自真人声音 |
| [Launch Video on X](https://www.remotion.dev/prompts/launch-video-on-x)（页面核对于 2026-11-10） | 一条提示词写完约 37 秒、8 个场景。界面要求用代码画出来。没有要求先访问真实产品。画幅写成 1080×700 | 采纳「每个场景写清观众看到什么」。不采用该画幅。有真实截图、录屏或官方素材时不用代码画界面。不在 SRT 核对前铺全片 |

文章里「十几分钟后得到 MP4」是作者的预期，不作为本流程的时间承诺。
