# 工作流

[入口](./SKILL.md) · [编排](./produce-prompt.md) · [脚本](./script.md) · [音色](./tone.md) · [素材](./resources.md) · [音效](./sfx.md) · [质量门](./quality.md)

本文件只规定顺序、交接物和停止条件。某一阶段怎么做，打开该阶段点名的文件。这里不重复那些规约，也不写 Remotion 组件。

核对日期：2026-11-10。流程图见 [Remotion-AI-Video-Workflow.mmd](../Remotion-AI-Video-Workflow.mmd)。工具与许可见 [Video.md](../Video.md)。

## 用语

| 用语 | 含义 |
|---|---|
| 片种 | 产品介绍、独立口播、技术讲解。Video.md 称产品宣传、口播讲解；流程图把技术讲解写成技术布道。三者共用本顺序 |
| 制作脚本 | 旁白正文、只上屏的文字、素材和动作备注。三层分开 |
| 分镜 | 段落级的画面意图，不是逐帧分镜 |
| 主音轨 | 用来定时间的那一条声音。独立口播是确认过的录音或 TTS。有出镜素材时是剪顺后的原声 |
| 独立口播 | 没有真人出镜画面。本 Skill 里的 talking-head 与它同义：TTS 或只录音，加上字幕和动态图形。不要从一句提示词里变出一位出镜的人。用户另给摄像头成片时，改走出镜分支 |
| 短样片 | 长片先做的约 1～2 分钟。片子本身不长于这个长度时，第一版整片就是样片，仍要人看过再导出 |
| 代码绘制界面 | 用代码画出的产品界面，不是截图或录屏。素材清单里必须标明 |
| 质量门 | 进入下一个贵重阶段或正式导出前必须通过的检查 |

视频工程里的稿、清单、音轨放在该工程的 `production/`，不要写进 SkillsPocket。本目录的同名文件是规约，不是某一集的稿。

## 顺序

环境准备从立项之后就可以做，不必等配音。素材检索可以在分镜草案之后开始。音效可以先列候选，切点要等字幕时间轴。除此之外按表推进。用户本轮如果只要求做到某一阶段，做到那里就停。

| 阶段 | 打开 | 进入条件 | 交出 | 停下 |
|---|---|---|---|---|
| 0 环境 | 本文件「环境」；官方 Remotion Skill | 已有简报，或用户要求先搭工程 | 能预览的工程。首次再加一个最小渲染 | 执行安装或脚手架之前 |
| 1 立项 | 本文件「立项」 | 用户给出意图 | 确认过的简报 | 缺事实、缺片种或没说清有没有出镜素材 |
| 2 脚本与分镜 | [script.md](./script.md) | 简报已确认 | 视频工程里的制作脚本 | 用户确认分镜之前。此前禁止全长配音、铺全片和正式渲染 |
| 3 素材 | [resources.md](./resources.md) | 分镜草案已有；确认分镜时关键演示段的素材或缺口要一起看 | 素材清单，许可栏已填或标成待确认 | 许可不明的第三方素材不进画面 |
| 4 主音轨 | [tone.md](./tone.md) | 分镜已确认 | 样音通过后的主音轨 | 未确认分镜不合成。样音未通过不做全长 |
| 5 字幕时间轴 | [tone.md](./tone.md) 的「时间轴」。是否通过看 [quality.md](./quality.md) | 主音轨已确认 | 与这条音轨对应、校对过的 SRT | 没有音轨时不按字数估时间 |
| 6 画面 | 官方 Remotion Skill。素材怎么交到段落见 [resources.md](./resources.md) | 主音轨、SRT、素材清单齐全 | 短样片；通过后再扩展全片 | 长片在短样片通过前不铺开。正式渲染另按质量门 |
| 7 音效与配乐 | [sfx.md](./sfx.md) | 画面方向已由短样片确定；时间用 SRT | 分轨的音效和配乐，以及人听过的结论 | 只找到文件、没有试听，不算完成 |
| 8 质量门 | [quality.md](./quality.md) | 有一版含主音轨、字幕和音效的预览 | 必过项的通过记录 | 有必过项失败就不导出 |
| 9 导出与归档 | [quality.md](./quality.md) 的导出检查；归档物见下文 | 质量门已通过，用户同意导出 | 成片，以及可再编辑的工程、脚本、音轨、SRT、清单 | 上传和发布由人确认 |

改主音轨、语速或停顿之后，回到阶段 5，并重做受影响段落的画面和音效时间。不要只把画面拉长、沿用旧 SRT。

## 立项要收齐的项

- 片种、主题、受众、发布平台。
- 画幅。未指定时用 1920×1080、30 fps。已有工程沿用它的 composition。竖屏只在简报要求时使用。
- 时长。未写死秒数时，成片长度跟随主音轨，另加约定的片头片尾。「大约 N 秒」只约束写稿，不代替实测时长。
- 风格：背景、配色、字体若用户有要求就记下。没有要求时，首版用深色背景、底部字幕，信息层级先统一。
- 是否已有真人出镜成片。没有则按独立口播：TTS 或只录音，加字幕和动态图形。有则走下面的分支。
- 是否商用。商用时模型和素材许可分开核对，见 [tone.md](./tone.md) 与 [resources.md](./resources.md)。
- 事实从哪来。用户的经历和产品数据由用户提供。网页和仓库可以查，查不到的数字不要写进旁白。

## 两条画面分支

分支在立项决定，阶段表不变。

| | 无出镜（默认，含独立口播） | 用户提供了出镜成片 |
|---|---|---|
| 主音轨 | 录音或 TTS，规则在 [tone.md](./tone.md) | 剪顺后的原声。不为同一篇稿再做一条 TTS 去替换它 |
| 分镜多标的内容 | [script.md](./script.md) 的三层 | 同一文件里的出镜列：何时露脸、何时盖 B-roll |
| 画面 | 字幕、截图、录屏、图解、动态图形 | 出镜成片为底层；B-roll 只盖画面，原声连续 |

声画细节以 [Video.md](../Video.md) 第 8 节为准：辅助录屏自带的解说默认静音；主音轨只留一份，避免双声。

## 环境

官方 Skill 未装时，把 `npx skills add remotion-dev/skills` 给用户看，同意后再执行。新建工程用官方 Skill 当时的脚手架，把完整命令给用户看再跑，不在本文件写死一份会过期的参数。

首次使用：先渲染一个最小例子，证明预览和导出能通。几秒钟、深色背景、一行中文字幕即可。这不是正片，也不要在这一步生成配音。

安装依赖若因网络停下，再询问是否按 Smartpigai 文章里的做法改用国内镜像。镜像不是默认步骤。

配音环境不在这一阶段安装。AudioSmith 与 Edge TTS 的调用条件见 [tone.md](./tone.md)。

## 归档时留下什么

- 可编辑的 Remotion 工程。
- 制作脚本、素材清单、主音轨、SRT。
- 需要署名的第三方素材的署名文本。
- 短样片里已经确定的背景、字体、动画密度。下一支片子先复用，不要重新摸索。
- 听过、以后还要用的音效，按 [sfx.md](./sfx.md) 记进个人库索引。

封面、标题、简介和实际上传由人做。Agent 可以起草，不代替发布。

## 与两份外部材料的差异

主人的过程以 [Video.md](../Video.md) 为准。下面两份材料里与它不一致的地方，不覆盖本文件。

| 来源 | 核对到的内容 | 本流程怎么取 |
|---|---|---|
| [Smartpigai 的文章](https://x.com/Smartpigai/article/2073753428212478384)（2026-07-05，标题「Claude + Remotion 做自媒体视频 · 全网最详细教程」） | 先确认分镜，再配音，再渲染；装依赖和跑命令先问；第一次先做最小例子；1920×1080；时长跟随配音；底部字幕；深色背景；用口语描述声音；搭建时写的是 Edge TTS | 确认门、先问命令、最小例子、画幅、时长和字幕采纳。配音在 AudioSmith 可用时不走 Edge TTS |
| [Launch Video on X](https://www.remotion.dev/prompts/launch-video-on-x)（页面核对于 2026-11-10） | 一条提示词写完约 37 秒、8 个场景和帧数。终端、主页、聊天等界面是要求用代码画出来的。页面没有要求先访问真实产品或下载截图，画幅写成 1080×700 | 采纳「每个场景写清观众看到什么」。不采用该画幅。有真实截图、录屏或官方素材时不用代码画界面。分镜仍要先确认 |

文章里「十几分钟后得到 MP4」是作者的预期，不作为本流程的时间承诺。
