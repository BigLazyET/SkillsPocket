本文件是每次使用本 Skill 时的第一阶段。它核对简报、素材和工具，分出硬停和建议。硬停没解除之前，不配音、不铺画面。建议写明之后就可以继续后面的阶段。

核对日期：2026-11-10。工具名单和许可以 [Video.md](../Video.md) 为准。这里不写 Remotion 组件，也不复制社区 Skill 的仓库。

## 硬停

继续做会编出实质内容，或会越界时，立刻停下，列出缺的项，等用户补上。

只包括：

- 形态 A、B、C 两可，或互相冲突
- A 没有用户认定的出镜成片路径，或 B 没有讲解音频（或含这条人声的视频）路径
- C 既没有脚本或要点，也没有允许起草
- 已经要使用的素材许可不清，或和商用冲突
- 下一步会改变音色、形态、付费或云端工具、许可敏感的素材

不要编造产品、音色、经历或没给过的媒体。缺的截图不要画成界面。缺的出镜不要用素材库里的人代替。

下面这些不硬停。写进准备结论，用户否定再改：

- 语言：简报里已经能看出就采用看出的语言
- 画幅：建议 1920×1080，或简报里的平台默认。写明建议，不静默改成另一个尺寸
- 字体：没点名时建议 Video.md 第 7 节的 Noto CJK。点名的文件不在时，问是要文件还是改用这项建议，不静默替换
- 片种：简报清楚就写上。又像产品介绍又像口播时，记成混合片并继续，不要为了凑成唯一标签停下
- 社区 Skill：按 [workflow.md](./workflow.md) 的「画面」推荐最合适的一个。用户拒绝或当时没有，用官方 Remotion skills 和已有素材继续

只读检查可以做：路径是否存在、技能列表里有什么、本机是否听得到 AudioSmith。安装、下载模型、克隆、删除、脚手架和正式导出，先把命令给用户看，同意后再执行。预览和短样片的同意范围见 workflow「命令要不要再问」。

## 先确认形态

三种形态互斥。开工回复里写明是哪一种。用户已经说清就不要再问一遍，但要把判定写出来。判不清就停。

| 形态 | 含义 | SRT 从哪来 |
|---|---|---|
| A 真人出镜视频 | 有一个真人对着镜头的画面，成片里要安排这个镜头 | 与画面一致的那条人声。做法在 [tone.md](./tone.md) |
| B 真人讲解音频 | 有真人说过的声音，没有要布局的出镜表演。声音可以是音频文件，也可以在一条视频的音轨里 | 这条讲解的人声。做法在 [tone.md](./tone.md) |
| C 没有真人只有脚本 | 没有真人录音，也没有出镜表演。只有脚本或要点 | 确认稿和样音之后的成品合成。做法在 [tone.md](./tone.md) |

片种不是形态。产品介绍、口播讲解、技术讲解都可以是 A、B 或 C，也可以在一支片子里同时出现。画面工具不由片种单独决定。

判定：

- 用户给了出镜表演，要在成片里出现这个人：A。产品介绍加上这个人，仍然是 A，产品镜头和出镜布局可以各选工具。
- 用户写「只有真人讲解视频」：按 B。若画面明显是人对着镜头讲，和这句话冲突，停下来问。
- 同时有出镜视频和另一条讲解音频：优先 A。SRT 只用和画面一致的那条人声。不能确定哪一条跟画面一致，停下来问。
- 既有稿又有真人录音：不是 C。录音对得上出镜表演就是 A，否则是 B。稿只用来校对听写。
- 用户要做一支片子，但只给了话题：视为允许起草，形态标为 C，稿留到 [script.md](./script.md) 写完并确认。他明确不要代写，又没有稿，才停下。
- 以上都无法归入一条：停下来问。

出镜镜头的形状、位置和运动到 [script.md](./script.md) 写成建议，交给用户看。不在这里选定，也不默认圆形或画中画。形态确认之后不要自动改成另一种。

## 检查清单

硬停行未就绪，就停。建议行写成「建议」或「就绪」，不因为还没亲口确认而停掉整轮。

| 项 | 怎么核对 | 结论 |
|---|---|---|
| 形态 | 用上一节归类 | 硬停：不是唯一的 A、B 或 C |
| A 的成片 / B 的声音 | 打开路径 | 硬停：该形态的文件读不到。不先合成一条代替 |
| C 的稿 | 看有没有脚本、要点，或做片的请求 | 硬停：没有文本，并且不准起草 |
| 许可 | 已要使用的第三方文件有没有许可 | 硬停：不清，或商用片上的 CC BY-NC。这条不进画面 |
| 音色 | 形态 C 在合成前才需要 | 不在准备阶段硬停。没有方向时，合成前问。不替他选定，也不自动改去 Edge TTS |
| 语言 | 看简报 | 建议：采用能看出的语言，写明 |
| 画幅 | 看简报或平台 | 建议：1920×1080，或平台默认。写明 |
| 片种 | 看简报在讲产品、口播还是技术 | 建议：清楚就记下。混合就写混合，并列出各段主要看什么 |
| 字体 | 点名的文件是否存在 | 建议：没点名用 Noto CJK。点名的文件缺失就问，不静默替换 |
| 事实 | 产品名、地址或文件能否指回用户 | 没有可指的产品却要介绍该产品：硬停，不编一个。其余缺口记在脚本里 |
| 识别 | 留到 [tone.md](./tone.md) | 准备阶段不因为 whisper 或 AudioSmith 还没试过就停下。两条都失败、又要写 SRT 时才停 |
| AudioSmith | 仅当会话在主人的 Mac 上时访问 `GET http://127.0.0.1:3901/health`。端口以应用为准 | 远程会话不连接 `127.0.0.1`。说明够不到。形态 C 要合成时再问换机器或 Edge TTS |
| 官方 Remotion skills | 技能列表里有没有创建、markup、Studio、渲染、字幕。目录名以安装结果为准 | 要做画面还没有时，给出 `npx skills add remotion-dev/skills`，同意后再装。写脚本不必等它 |
| 社区 Skill | 按这部片子主要看的东西，看 video-shotcraft 或 video-talkcraft 是否已安装 | 建议安装最合适的一个，命令在下面。没装或用户拒绝：官方 skills，写入 `production/paths.md` |
| 渲染工具链 | 用户指出的工程里有没有 Remotion | 没有工程时，脚手架先问。同意后的第一次预览可以是几秒字幕的最小例子，这不是正片，也不配音 |
| 演示素材 | 路径或页面当时是否打得开 | 缺的记成缺口。不画假界面，也不为此停掉整轮 |
| 风格仓库 | 不开工就逐个安装 | 自家样式即可。用户点名某一个时，只核对那一个能否打开 |
| 帧率 | 看工程或简报 | 未指定不挡住。新建工程用 30 fps。用户另有帧率就改 |

社区 Skill 的安装命令，只在推荐并且用户同意后执行：

```bash
npx skills add Vincentwei1021/video-shotcraft
npx skills add Vincentwei1021/video-talkcraft
```

安装依赖若因网络停下，再问是否按 Smartpigai 文章里的做法使用国内镜像。镜像不是默认步骤。
