## 第一次使用 Remotion 个人视频 Skill

让 Agent 能读到本仓库、视频工程和本轮使用的素材。在 SkillsPocket 中开工，可以直接说「请读取 `Skills/remotion-personal-video/SKILL.md`，按下面的简报制作视频」。如果在别的视频工程里开工，给出本仓库里 `SKILL.md` 的绝对路径，或者调用已安装的 `remotion-personal-video`。视频工程和成片产物放在你指定的目录。

**最省来回的写法是分清「必须」「偏好」「交给 AI」「禁止」。** 必须项写清验收条件，偏好允许合理调整。没偏好的项目可以填「交给 AI，记录决定并继续」。素材给附件、实际路径或链接，并说明用途。只有主题和目标时也可以先让 AI 调研并写逐镜稿。

### 先选人声路线

| 形态 | 什么时候选 | 开工时提供什么 |
|---|---|---|
| **A · 真人出镜口播** | 观众会看到真人讲话 | 给现有视频路径、采用哪版以及是否允许剪口误。还没录就写「先交制作稿和录制稿，等我回传视频」 |
| **B · 真人讲解** | 以真人声音讲解，画面主要看录屏、素材或图解 | 给音频路径，或给视频并说明使用哪条音轨、原画面能否当 B-roll。需要新录或补录时说明范围 |
| **C · AI 旁白** | 旁白由 TTS 生成 | 给主题、要点和音色偏好。AI 起草逐镜稿和台词。确认稿和样音后，再合成全长 |

A/B 如已有和当前原声匹配的 SRT，一起提供。新录或补录才需要独立的录制稿。C 从逐镜稿提取纯台词供 TTS 使用。

### 可直接复制的完整提示词

把方括号里的内容换成自己的信息。与本轮无关的字段可以删掉。把「本轮做到哪里」写具体，Agent 就知道何时该交付、何时该继续。

```text
请使用 remotion-personal-video Skill。若未加载，请读取 [SkillsPocket 中 SKILL.md 的路径]。
按此简报推进。未指定的可逆偏好由你选择并记录；只在缺少关键事实或素材、
涉及未授权操作、或到需要我审看和试听的阶段时集中问我。

【目标与内容】
- 主题 / 产品 / 版本：[讲什么，相关站点、仓库或文件]
- 片种：[产品介绍 / 口播 / 技术讲解 / 混合]
- 观众：[角色、已有知识、最关心的问题]
- 观看场景 / 平台：[发到哪里，观众怎么观看]
- 看完要知道或做什么：[一句核心信息，是否需要行动引导]
- 必讲内容与顺序：[列优先级，注明要完整上屏的命令、数字、品牌名]
- 禁讲内容：[未公开功能、客户信息、未经证实的数字等]
- 调研范围：[可以引用哪些公开来源、项目文档或我给的事实]

【交付规格】
- 画幅 / 尺寸 / 帧率：[例如主版 1920×1080、30 fps，另要 1080×1920]
- 时长：[目标 60–75 秒，或硬性上限 90 秒]
- 语言：[旁白、字幕和屏幕文字用什么语言；是否保留英文术语]
- 字幕：[烧录 / 独立 SRT / 两者都要；单行按 Skill 默认；是否需要词级强调]
- 输出：[例如 MP4（H.264/AAC）、SRT、可编辑 Remotion 工程]
- 商用和发布：[个人 / 对外商用，署名放片尾或描述；上传由谁处理]

【人声】
- 形态：[A 真人出镜 / B 真人讲解 / C TTS]
- 已有原声：[路径、采用哪版、保留或可剪的片段、对应 SRT；没有则写无]
- 新录或补录（A/B）：[需要录哪些段；是否先交录制稿，等我回传]
- 出镜布局（A）：[哪些镜头露脸、全屏或画中画、必须避开的画面区域]
- 音色（C）：[指定引擎或声音；语速、语气、参考和专名读法；允许哪些备选]

【画面与声音】
- 风格：[例如清爽技术演示、浅底深字、中等节奏；或由 AI 定]
- 参考：[链接 + 时间段；只参考构图、节奏或动效中的哪些部分]
- 视觉约束：[品牌色、Logo、字体、开场、结尾、转场、动画密度、无障碍需求]
- 素材：[每项写路径或附件、内容、源片段、必须用或可选、许可或出处]
- 真实演示：[要看到哪些界面、操作和结果；缺画面时可否用标明为示意的图解]
- 辅助素材：[默认优先复用合用的 Skill / 模板 / 工程资源；
  我提供的通用素材可补位。另列明确指定或禁止使用的素材]
- 音效 / 配乐：[要不要、什么听感、哪些动作需要强调、哪些地方安静]

【执行与交付】
- 工程：[绝对路径；已有项目写 composition ID，新项目写目标目录]
- 本轮做到：[只做调研和稿 / 出录制稿 / 约 15 秒初剪 / 全片并走正式导出确认]
- 审看重点：[例如字幕不挡操作，点击声跟点击帧，结果画面留足阅读时间]
- 可以直接做：[例如读取附件和工程、查公开资料、启动 Studio、渲染预览]
- 需要单独确认：[例如安装、下载模型、脚手架、付费、外部云服务、正式导出]
- 审看后继续方式：[例如初剪通过后按工作流继续全片；长片样片仍给我确认]
- 缺项处理：[可选项用默认或省略；关键缺口列清影响和选项后再问]
```

### 填写表

**优先写**适合每次开工填写。**按情况**只在适用时写。**可委托**可以留给 AI，并明确你的边界。

| 项目 | 何时填 | 填什么或怎么写 |
|---|---|---|
| 主题、产品和版本 | 优先写 | 一句话说明主题。产品介绍给实际产品名和地址；技术讲解给版本或运行环境 |
| 目标 | 优先写 | 写观众看完要理解、相信或完成的一件事，如「能独立完成首次导出」 |
| 目标观众 | 优先写 | 写角色和知识起点，如「懂 Git、第一次接触 Remotion 的前端开发者」 |
| 片种和叙事 | 可委托 | 产品介绍可指定「问题 → 演示 → 结果」。混合片可按段分配口播、录屏和图解 |
| 观看场景和平台 | 优先写 | 例如课堂投屏、产品页嵌入、手机信息流。需要遵循平台规格时附链接或给出数值 |
| 必讲、选讲、禁讲 | 优先写 | 区分必须保留的操作、可删的背景和禁止公开的细节。标明是否允许改写 |
| 调研与事实来源 | 按情况 | 给 README、帮助文档、用户确认过的数据、案例原文，说明能否查公开资料。敏感内容给脱敏版本 |
| 行动引导和固定文案 | 按情况 | 给结束语、按钮文案或链接；命令、价格、免责声明等需原样展示时写明 |
| 尺寸和帧率 | 优先写 | 写像素和画幅，如 `1920×1080 / 16:9 / 30 fps`。未定可写「按发布场景建议」 |
| 多画幅交付 | 按情况 | 区分主版和附版；说明竖版能否重排镜头和字幕，哪些操作区不能裁 |
| 时长和节奏 | 优先写 | 区分「约 60 秒」和「最多 60 秒」。写明希望快切、稳一点还是给操作留读时间 |
| 语言、术语和读法 | 按情况 | 区分旁白、字幕和屏幕文字语言。给产品名、缩写、版本号、数字单位的读法 |
| 字幕和无障碍 | 可委托 | 烧录、独立 SRT 或两者。中文默认单行，横屏和方形最多 16、竖屏最多 12 个全角等效字，并按实际宽度验收。可注明字幕位置或视觉限制 |
| 编码和文件 | 按情况 | 无指定时可用 MP4（H.264/AAC）。另有字幕、透明视频、分轨、响度或可编辑工程要求时单列 |
| A/B 的音视频 | 按情况 | 用实际路径并指明版本。视频带多条声音时注明哪一条是主音轨、哪些辅助原声可保留 |
| A/B 的剪辑和补录 | 按情况 | 指定哪些片段能删、哪些表述必须保留；新录时注明本轮只出稿还是等素材回传后续做 |
| A 的出镜 | 按情况 | 指定哪些时刻要露脸、露脸区域、画中画位置、切到录屏时是否保留原声 |
| C 的 TTS | 按情况 | 给指定的引擎或声音，以及听感、语速和可接受的备选；如果引擎依赖本机或在线服务，写明执行环境 |
| 风格和参考 | 可委托 | 写可观察的特征，例如「冷色背景、截图原色、操作时局部放大」。参考片标时间段和想借鉴的点 |
| 品牌、片头和片尾 | 按情况 | 给 Logo、字库、配色、品牌包、固定片尾或系列样片；注明哪项必须沿用 |
| 镜头、转场、动画和特效 | 可委托 | 指明用途而非只给名字，如「点击时出现高亮，保存结果停留供阅读」。未指定的细节由 AI 按逐镜稿补足 |
| 真实画面和素材清单 | 按情况 | 附件或可读路径，说明每份素材证明什么、要用哪段、是否必须用和许可情况。真实演示尽量提供录屏或可访问的真实产品 |
| 辅助素材与替代方案 | 可委托 | 写「先用 Skill/模板资源，合适即可用」。可选装饰不足时可简化。产品画面缺失时，说明是否接受明确标注的示意图 |
| 音效、配乐和静音 | 可委托 | 写听感和目的，如「保留真实操作声，配乐压低，成功时一声轻提示」。按需写明无配乐、禁用素材或必须试听的片段 |
| 许可、隐私和预算 | 按情况 | 说明是否商用、哪些素材可入片、如何署名、预算上限和允许访问的服务。密钥留在本机配置 |
| 工程、入口和输出目录 | 优先写 | 新建就给目标位置；续做给工程路径、composition ID 和上一版文件。需要保留的版本写明 |
| 本轮范围与交付物 | 优先写 | 例如「只交调研和逐镜稿」「交 A 的录制稿」「到十五秒初剪」「审看后完成 MP4、SRT 和归档」 |
| 允许的操作与审看 | 优先写 | 例如「本轮可直接启动 Studio 和渲染预览；装包、下载模型、云服务和正式导出前列明具体操作」 |
| 通过条件与缺项处理 | 可委托 | 给本轮最想验证的 2–3 点。可选缺项让 AI 用默认或省略；缺关键事实、指定素材或权限时集中提问 |

### 一份填写好的示例

下面是虚构项目，实际使用时替换成自己的可读路径和来源。

```text
使用 remotion-personal-video，做一条给第一次使用「项目看板」的团队成员看的
技术讲解。看完他们要能创建看板并验证保存结果。以附件里的使用说明和界面录屏
为准，必须演示「新建 → 填标题 → 保存 → 回到列表确认」，不提没有依据的效率数字。

形态 B。主音轨用附件 narration-final.wav，已有同版 captions.srt，请先核对再复用。
旁白不重写；发现关键步骤没讲到就标出来。画面用 screen-recording.mp4 的
00:08–00:31；保留按下保存和看到结果的镜头，录屏的辅助解说静音。

主版 1920×1080、30 fps，目标 60–75 秒，简体中文旁白与字幕，术语保留英文。
浅底、清晰的技术演示风。字和动效别挡住关键操作，成功时可用一个轻提示音，
其他装饰优先用 Skill 自带资源。没有合适配乐就省略。

使用 /Users/me/Videos/board-demo 的现有工程，composition 为 BoardDemo。
先交逐镜稿和约 15 秒初剪，本轮可直接开 Studio 和渲染预览。初剪优先检验
字幕切换、保存动作与提示音的同步，以及结果有没有留足阅读时间。
正式导出等我审看确认，计划交 MP4、独立 SRT 和可编辑工程。
```

写清偏好可以减少开工阶段的追问。A/B 需要真人录制时，制作时间轴要等成品原声回传。C 的全长配音要先确认台词和样音。铺全片前要看十五秒初剪，适用时还要确认长片样片。正式导出和涉及安装、付费或外部服务的动作，按已给的具体授权和工作流推进。详见 [制作工作流](Skills/remotion-personal-video/workflow.md)。
